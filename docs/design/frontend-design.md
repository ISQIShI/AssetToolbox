# 前端设计规范

状态：已采用。日期：2026-11-10。适用范围：`desktop/src/` 的全部界面工作，包括新增页面、组件、字段类型和文案。

本文是界面设计的唯一规范来源：视觉主张、令牌、布局、组件、状态和文案规则都以这里为准。组件职责、状态流转和请求映射等实现细节见[前端架构](../architecture/frontend.md)；本次从“网页式工作台”改为“桌面软件”的原因见 [ADR 0006](../decisions/0006-desktop-application-shell.md)，处理线主从结构的来历见 [ADR 0004](../decisions/0004-frontend-redesign.md)。令牌的实际取值以 `desktop/src/styles/tokens.css` 为准，本文表格与其同步维护。

## 设计主张

- **产品**：本地资源处理工具。素材文件夹按顺序经过若干步骤（缩放、压缩），写回原处或另存，并且可以续跑和恢复。
- **使用者**：游戏开发者和技术美术。日常开着引擎编辑器、DCC 和 IDE，处理的是成百上千个文件的文件夹，在意每一步做了什么、文件是否安全。
- **主要任务**：配置一条处理线并运行；运行中随时能看到进度并取消；出问题后继续、重试或恢复。

**它是一个桌面软件，不是网页。** 判断一处设计是否合格，先问：把它放在引擎编辑器和 IDE 旁边，是否像同一类东西。具体表现为：

| 网页的做法（不采用） | 软件的做法（采用） |
| --- | --- |
| 系统标题栏下面再放一条带产品名和导航的页头 | 自绘标题栏；左侧活动栏切换工作区 |
| 大标题、宽行距、居中或限宽的“阅读版式” | 13px 正文、30px 控件、紧凑的属性表单和数据表 |
| 操作按钮放在内容末尾或页脚 | 命令放在工作区顶部的命令栏，位置固定 |
| 文字都能选中，按钮显示手型光标，悬停加下划线 | 界面文字不可选中，光标保持箭头，悬停用底色反馈 |
| 网页字体、固定浅色 | 系统界面字体，跟随系统的浅色与深色 |
| 浏览器右键菜单、F5 刷新 | 屏蔽浏览器菜单和刷新，提供自己的快捷键 |
| 没有全局状态位置 | 窗口底部状态栏始终显示当前活动与工具健康状况 |

### 核心隐喻：处理线

处理页左侧的竖线是整个界面的骨架。文件从“来源”出发，自上而下经过编号的步骤，最后到达“写入”。编号就是执行顺序，这是界面上唯一使用序号的地方，因为内容本身确实是一个序列。

```
■ 来源            UI
│
① PNG 图片缩放     Sharp / libvips
│
② PNG 压缩        ⚠ 缺少依赖          ← 品红编号与缺件图标：缺少依赖
┊
③ JPEG 压缩       已停用              ← 空心节点 + 虚线：停用
│
④ MP3 压缩        LAME 4.0
│
⊕ 添加步骤                            ← 弹出菜单
│
■ 覆盖原文件       备份到 Backups
│
□ 扫描结果        538 个文件          ← 仅在扫描后出现
```

### 设计原则

1. **处理线是骨架**：所有和“怎么处理”有关的设置都挂在处理线的某个站点上。不要在处理线之外另开设置区。
2. **层级靠明度，不靠线**：窗口框架最深，侧栏次之，内容面更亮，控件最亮。相邻层级之间最多一条细分隔线。
3. **强调色只有一种**：`--accent` 表示“当前选中”“主命令”和键盘焦点。其余彩色只表达状态（成功、警告、失败、缺依赖），不作装饰。
4. **路径和哈希用等宽字体，并且可以选中复制**：它们是需要逐字核对的数据。其他界面文字用系统字体且不可选中。
5. **命令位置固定**：每个工作区的主要命令在顶部命令栏或详情标题行右侧；同一命令不随内容长短移动。
6. **作业全局可见**：同一时间只有一个作业，显示在工作区底部的作业栏；状态栏同时给出一句话状态。

### 外观（浅色与深色）

- `core/theme.ts` 在 `<html data-theme>` 上写入 `light` 或 `dark`，`tokens.css` 用 `:root[data-theme='dark']` 重定义同名令牌。组件里不写主题分支。
- 默认跟随系统（`prefers-color-scheme`），系统切换时即时生效。活动栏底部的外观按钮每点一次就在浅色与深色间切换一次；切换后的外观与系统一致时记为“跟随系统”，否则记为固定的浅色或深色。选择保存在 WebView 的 `localStorage`，不进入核心配置。
- 新增或调整颜色时，两套取值都要在所在背景上达到 4.5:1。

### 缺少依赖标记

`.missing-swatch` 是 14px 的品红缺件图标：虚线圆角方框里一个感叹号，表示“这里缺了一块”。它用 CSS 遮罩绘制，颜色取 `--missing`，与界面其他线条图标的线宽一致。它只能表示“处理工具缺少依赖”，出现在处理线站点、命令栏、步骤编辑器提示、工具页和状态栏；活动栏的“工具”项用品红计数徽标。不要把它用于其他错误。

### 字体

| 角色 | 字体栈 | 说明 |
| --- | --- | --- |
| 界面 | `Segoe UI Variable Text` → `Segoe UI` → `Microsoft YaHei UI` | 系统界面字体，与 Windows 自身一致；中文由雅黑 UI 显示 |
| 路径、哈希、扩展名 | `Cascadia Mono` → `Consolas` | 只用于需要逐字核对的数据 |

不打包任何字体文件，也不引入在线字体。全局开启 `font-variant-numeric: tabular-nums`，让进度、计数和体积对齐。

### 字号

只用四级：

| 令牌 | 大小 | 用途 |
| --- | --- | --- |
| `--t-small` | 12px | 提示、副标题、表头、状态栏、标题栏、活动栏标签 |
| `--t-body` | 13px | 正文、控件、列表项、分组标题（600）；行高 1.5 |
| `--t-title` | 15px | 内容区标题（`h2`） |
| `--t-figure` | 20px | 扫描结果与任务进度的关键数字 |

字重只用 400 和 600。不使用斜体、全大写和字间距放大的小标签。活动栏计数徽标和处理线节点编号是 11px 的图形内数字，不算正文。

### 间距、圆角与尺寸

- 间距：`--s-1` 到 `--s-7` 对应 4、8、12、16、20、24、32px。
- 圆角按层级：控件 4px（`--r-control`），分组面板 6px（`--r-panel`），弹出菜单与工作区左上角 8px（`--r-float`），状态徽标与处理线节点为全圆角。
- 窗口框架：标题栏 `--titlebar-height: 36px`，活动栏 `--activity-width: 64px`，状态栏 `--status-height: 24px`，命令栏 `--command-height: 44px`。
- 侧栏：处理线 `--rail-width: 264px`，任务列表 `--list-width: 288px`；窗口不超过 1000px 时为 236px 与 252px。
- 控件：普通 `--control-height: 30px`，小号 `--control-small: 24px`；属性表单标签列 `--label-width: 128px`（紧凑窗口 108px）。
- 内容区表单最大宽度 `--measure: 760px`，边距 `--pane-padding: 20px`（紧凑窗口 16px）。

## 布局

### 窗口骨架

```
┌──────────────────────────────────────────────────────────────────┐
│ ▣ 资源工具箱              来源文件夹名                 ─  ☐  ✕   │ 标题栏 36px，可拖动
├────┬─────────────────────────────────────────────────────────────┤
│处理│ 信息条（错误 / 成功 / 警告，按需出现）                       │
│任务│ ┌─────────────────────────────────────────────────────────┐ │
│恢复│ │ 当前工作区：命令栏 + 侧栏 + 内容区                       │ │
│工具│ │                                                         │ │
│    │ └─────────────────────────────────────────────────────────┘ │
│ ◐  │ 作业栏（有作业时）                                           │
├────┴─────────────────────────────────────────────────────────────┤
│ ● 就绪                              1 个任务可继续  处理工具 4/4  │ 状态栏 24px
└──────────────────────────────────────────────────────────────────┘
```

- 原生窗口关闭系统边框（`decorations: false`），标题栏由 `TitleBar.vue` 绘制：应用图标、名称、当前来源文件夹名，右侧是最小化、最大化、关闭。空白处带 `data-tauri-drag-region`，可拖动窗口、双击最大化。
- 活动栏、标题栏、状态栏同为 `--chrome`；工作区是从框架上抬起的一块，左上角圆角。
- 外壳是纵向 flex。**不要改用 CSS Grid 的固定行模板**：信息条和作业栏按需出现，Grid 自动放置会把工作区挤进错误的行。
- 工作区占满剩余高度，各分栏自己滚动，窗口本身不滚动（`body` 为 `overflow: hidden`）。
- 所有内容左对齐。只有数字列右对齐。

### 工作区

| 工作区 | 顶部命令栏 | 左栏 | 内容区 |
| --- | --- | --- | --- |
| 处理 | 步骤统计、写入策略；保存配置、扫描预览、开始处理 | 处理线 | 选中站点的编辑器 |
| 任务 | 无；命令在详情标题行右侧（继续未完成、重试失败项） | 可搜索的任务列表，每行带进度条 | 进度、详情、备份与恢复三个分组 |
| 恢复 | 来源选择（任务的备份 / 独立备份文件夹）与检查命令 | 无 | 检查结果：筛选工具栏、数据表、底部的计数分页与恢复命令 |
| 工具 | 工具健康状况；刷新依赖状态 | 无 | 处理工具列表（缺依赖的排在最前并展开）、识别的资源类型、核心目录 |

### 窗口尺寸

- 原生窗口默认 1220×850，最小 840×620。最小尺寸下不能出现横向滚动，E2E 会检查。
- 这是桌面软件，不做手机宽度的布局。低于 840px 只可能出现在浏览器调试中，不需要适配。
- 内容区表单按容器宽度调整：写入方式的两个选项在 520px 以内纵向排列，扫描数字变为两列；参数行在 420px 以内改为标签在上。

## 组件

### 图标

`Icon.vue` 提供一组自绘的 16px 单色线条图标，颜色跟随文字，不引入图标库。图标只作辅助识别：带文字的按钮图标在文字左侧；只有图标的按钮必须有 `aria-label` 和 `title`。新增图标在 `Icon.vue` 的路径表里登记，线宽和网格保持一致。

### 按钮

| 类 | 外观 | 用途 |
| --- | --- | --- |
| `.button` | 控件底色加细边框 | 普通命令 |
| `.button.primary` | 强调色实心 | 每个区域最多一个，表示下一步最该做的事 |
| `.button.quiet` | 无边框，悬停才有底色 | 次要命令、关闭 |
| `.button.danger` | 红色文字，悬停红色浅底 | 删除步骤等破坏性命令，放在命令行最右侧 |
| `.button.small` | 24px 高 | 步骤命令、表格工具栏、分页 |
| `.button.icon-only` | 正方形 | 只有图标的命令 |

按钮文字说清楚会发生什么。有快捷键或需要补充说明的命令用 `title` 给出。停用的按钮要能从周围文字看出原因，例如命令栏会写出哪一步缺少依赖。

### 表单

- 字段是属性表单的一行：`.field` 两列，标签在左（`.label`，`--label-width` 宽），控件在右，提示（`.hint`）在控件下方。`.field.stacked` 是标签在上的变体，只用于横向排布的来源选择栏。
- 每个控件都必须有关联的 `<label for>`，ID 用 `useId()` 生成，不能用标签文字拼 ID。
- 相关字段放进 `.group` 分组面板，面板内第一行是 `h3` 标题。
- 路径一律用 `PathField`：等宽输入框加“浏览…”按钮，可直接粘贴路径。
- 参数一律由 `ParameterFields` 按核心返回的字段描述渲染。数值框限宽 140px，下拉框限宽 320px；数值字段的提示自动合成“范围 a–b”和扩展提供的 hint。
- 勾选框、单选和下拉箭头是自绘的（`appearance: none`），勾选色为强调色。立即生效的开关用 `input.toggle`（“启用此步骤”）。
- 两三个互斥选项用 `.segmented` 分段选择（恢复来源、恢复状态筛选），内部是视觉隐藏的单选框。

### 处理线站点

- 端点（来源、写入）是 10px 实心方块；步骤是 20px 圆形编号；扫描结果是空心方块；添加步骤是空心圆加号。节点外有一圈与所在行底色相同的描边，把竖线在节点处断开。
- 停用步骤：空心编号，该段竖线变为虚线，副标题写“已停用”。
- 缺少依赖：编号底色变为品红，副标题显示缺件图标和“缺少依赖”。
- 每个站点是一个圆角列表项按钮，悬停显示 `--hover`，选中显示 `--accent-wash` 且 `aria-current="true"`。端点带 `data-station`，步骤带 `data-step-id`，供测试定位。
- “添加步骤”使用两级非模态选择器：先选操作，再选资源类型；不平铺所有“格式 × 操作”组合。首层显示支持的格式摘要，次层显示扩展名并提供返回按钮。可按名称、ID 或扩展名搜索；没有匹配项时给出提示。内容从目录生成，缺依赖的组合仍可添加，由步骤编辑器提示获取方式。
- 选择器用 `position: fixed` 按按钮定位，宽 320px、高度最多 360px，下方空间不足时向上展开并限制在窗口内；仅选项列表滚动，标题和搜索始终可见。点击别处、焦点移出、窗口尺寸变化、处理线滚动或进入忙碌状态时关闭。
- 打开和切换层级时聚焦搜索框；上下方向键移动选项，Home/End 定位首尾（搜索框中保留文本编辑行为），Enter/空格激活按钮，资源类型按钮上按左方向键返回操作列表。Esc 退出及添加完成后焦点回到添加按钮；取消选择不修改处理线。

### 命令栏、步骤编辑器与工具列表

- 处理页命令栏左侧显示启用步骤数和当前写入策略。写入策略是一个可点击的小标签，点击定位到“写入方式”；不备份时为警告色。缺依赖时改为显示品红提示和“查看获取方式”入口。
- 同一操作切换处理工具时保留操作参数，工具参数改为目标操作适配器的默认值；切换操作才重置两组。工具参数标题包含工具与操作名称，不能显示其他操作的专属字段。
- 步骤编辑器自上而下：标题与“启用此步骤”开关；步骤命令行（上移、下移、恢复默认参数，最右是删除步骤）；缺依赖提示；“步骤组合”分组；操作参数分组；工具参数分组。
- 工具列表是一个面板里的可展开行，使用原生 `details/summary`，行首箭头随展开旋转，行尾是状态徽标（`.state`）。支持 Enter 和空格操作。
- 依赖管理位于展开行内，显示当前/核验版本、来源域名与状态。根据状态提供“获取并安装”“更新到核验版本”“修复安装”或“重新安装”；手动项保留说明及获取链接。所有安装动作在作业运行时停用；进度与取消使用作业栏。不要把核验版本写成上游最新版。

### 作业栏

- 停靠在工作区底部，`--pane` 底色，任何页面都显示。
- 运行中：标题、阶段、进度条、`已处理 / 总数`、耗时、取消；第二行是当前文件（等宽、单行省略）。总数未知时进度条来回扫动。
- 结束后：结论图标与文字（已完成 / 完成，N 个失败 / 已取消 / 未完成），关键数字，打开报告、查看任务、关闭。
- 预览类作业（扫描预览、检查备份）成功拿到结果后自动收起，结果显示在所属页面；失败时保留作业栏显示错误。
- 关闭作业栏只隐藏界面，不删除任务和报告。

### 状态栏

窗口最底部的一行，始终可见。左侧是一句话活动状态（就绪 / 正在运行：作业名 / 正在安全退出），带状态圆点；右侧是可点击的概况：可继续的任务数（跳到任务页）、处理工具可用数（跳到工具页，缺依赖时为品红并带缺件图标）。状态栏只放全局事实，不放命令。

### 信息条与徽标

- `.callout` 是圆角信息条，按 `danger / warn / ok / missing` 取对应浅色底，行首有状态图标或缺件图标。全局错误和成功提示显示在工作区顶部，可以关闭；局部提示放在对应内容上方。
- `.badge` 是全圆角小标签，用于对象的状态（任务状态、工具可用性、恢复文件状态）。行内的状态文字用 `.tone`。

### 表格

数据表放在带边框的圆角面板里（`.grid-frame`）或独立滚动区里。表头吸顶，`--pane` 底、12px 常规字重；行高紧凑，悬停有底色；数字列右对齐且不换行。已勾选的行使用 `--accent-wash`。

## 交互约定

- **选择与光标**：`body` 为 `user-select: none; cursor: default`。输入框、`.path` 和 `.selectable`（错误信息、安装说明）可以选中复制。按钮不使用手型光标。
- **悬停与选中**：悬停用 `--hover` 底色；列表中的当前项用 `--accent-wash`；活动栏当前项另有强调色竖条。不使用下划线表示可点击。
- **快捷键**：`Ctrl+1`–`Ctrl+4` 切换处理、任务、恢复、工具；`Ctrl+S` 在处理页保存配置。快捷键写在对应控件的 `title` 里。
- **浏览器行为**：生产构建屏蔽浏览器右键菜单（文本输入框除外）以及 F5、Ctrl+R、Ctrl+P、Ctrl+F 等浏览器快捷键，避免刷新丢失未保存的编辑。开发模式保留，便于调试。
- **关闭窗口**：标题栏关闭按钮调用原生 `close()`，与系统关闭走同一条路径；有作业时先协作取消。

## 状态语义

| 状态 | 颜色 | 出现位置 |
| --- | --- | --- |
| 已完成、可用、节省体积 | `--ok` | 任务状态、工具状态、体积变化为减少 |
| 可继续、已取消、结果过期、体积增大、检查不完整 | `--warn` | 任务状态、作业结论、扫描结果 |
| 失败、冲突、错误、无法读取 | `--danger` | 作业结论、恢复状态、任务状态 |
| 缺少依赖 | `--missing` 加缺件图标 | 活动栏、处理线、步骤提示、工具页、命令栏、状态栏 |
| 中性（正在处理、已开始恢复、可恢复） | `--text-2` | 其余状态 |

体积变化统一用 `sizeChange()` 格式化：节省显示为 `−2.0 KB`（绿色），增大显示为 `+100 B`（警告色）。不要直接显示 `savedBytes` 的原始符号。

## 文案

### 词汇表

界面用使用者的语言，架构文档用实现的语言。两者对应如下，新增界面文字时沿用左列：

| 界面用词 | 架构 / 协议术语 |
| --- | --- |
| 处理线、步骤 | pipeline、step |
| 资源类型 | resource type |
| 操作 | operation |
| 处理工具 | provider |
| 操作参数 / 工具参数 | `parameters` / `providerOptions` |
| 来源文件夹 | `sourceDir` / `folder` |
| 写入方式：覆盖原文件 / 另存到新文件夹 | `saveMode`: `overwrite` / `saveAs` |
| 替换前备份原文件 | `backupEnabled` |
| 扫描预览 | `preview` |
| 检查备份 | `restore-preview` / `restore-export-preview` |
| 任务的备份 / 独立备份文件夹 | 任务恢复 / `restore-export` |
| 外观：浅色 / 深色，与系统一致时注明“跟随系统” | `theme`（仅前端） |

### 动作名称一致

同一个动作从按钮到作业栏标题使用同一个名字：

| 按钮 | 作业栏标题 |
| --- | --- |
| 扫描预览 | 扫描预览 |
| 开始处理 | 处理资源 |
| 继续未完成 | 继续未完成 |
| 重试失败项 | 重试失败项 |
| 检查备份 / 检查独立备份 / 重新检查 | 检查备份 |
| 恢复所选 N 项 | 恢复所选文件 |

### 写法

- 用平实的动词和句子，句号结尾。不用感叹号，不道歉，不用“您”。
- 错误说清楚发生了什么、怎么办：“第 2 步的处理工具缺少依赖，安装或停用后才能开始处理。”
- 空状态说明这里会出现什么、怎样开始：“还没有任务。在“处理”页开始处理后，进度会保存在这里。”
- 计数写成句子或带单位的短语（“3 / 4 个步骤已启用”），不要用 `A · B · C` 拼接元数据。
- 不在标题上方加小标签，不用全大写英文标签，不用“WORD — 片段”式标题。

## 动效

主动动效只有三处：作业栏进度条的宽度过渡与总数未知时的扫动；状态栏圆点在忙碌时的明暗变化。其余都是对操作的直接响应（开关滑块、展开箭头旋转），不超过 0.12 秒，不加入场动画。`prefers-reduced-motion` 时全部动画缩短到近似为零。

## 可访问性底线

- 键盘可以到达所有操作，焦点统一显示 2px `--accent` 轮廓。标题栏的窗口按钮不进入 Tab 顺序（系统快捷键已覆盖）。
- 图标性元素（图标、节点、缺件图标、色键）设 `aria-hidden`，含义由文字表达；只靠颜色区分的状态必须同时有文字。
- 文字与所在背景的对比度不低于 4.5:1，浅色与深色都要满足；`--text-3` 只用于占位、停用和装饰线。
- 作业栏是 `role="status"` 且 `aria-live="polite"`；全局错误是 `role="alert"`。

## 扩展界面的方式

- **新增资源类型、操作或处理工具**：不需要改前端。添加步骤菜单、步骤编辑器、工具页和识别类型表都由 `bootstrap` 返回的目录驱动。
- **新增参数字段类型**：在 `ParameterFields.vue` 增加分支，并在扩展契约中登记；保持“标签在左、提示在控件下方”。
- **新增工作区**：在活动栏加一项（图标、两个字的名称、`Ctrl+数字`），命令放顶部命令栏，优先采用“侧栏 + 内容区”的主从结构；作业相关逻辑放进 `core/workbench.ts`，不要在视图里直接调用公共作业 API。
- **新增作业类型**：在 `workbench.ts` 的 `JobKind` 中登记，并决定它是否属于“预览类”（结果在页面内显示、作业栏自动收起）。

## 在浏览器中调试界面

在 `desktop/` 执行 `npm run dev:web`，打开 `http://127.0.0.1:1420`。开发模式下检测不到 Tauri 时，`core/api.ts` 改用 `core/preview-core.ts` 模拟核心：生成样例配置、任务、扫描和恢复结果，并模拟作业进度。它不读写任何文件，生产构建会剔除。浏览器中没有原生窗口，标题栏不显示窗口按钮，也不能拖动。

| 地址参数 | 效果 |
| --- | --- |
| `?missing` | pngquant 显示为缺少依赖 |
| `?empty` | 没有任务 |
| `?missing-auto` | LAME、Sharp 缺失，模拟安装后恢复可用，不下载或写文件 |
| `?updates` | 模拟存在新的核验版本 |
| `?duration=6000` | 模拟作业持续的毫秒数，默认 4000 |

模拟核心只用于看效果。行为验收以组件测试和原生 E2E 为准。

Vite 文件监听排除 `src-tauri/`，避免 Windows 原生构建锁定 EXE 时使浏览器预览报 `EBUSY` 并退出；前端源码热更新仍正常工作。

## 改动前后的核对清单

1. 在 1220×850 和 840×620 下截图，确认没有横向滚动、文字截断后仍可辨认。
2. 浅色与深色各看一遍：层级分明，状态色可读。
3. 运行一次扫描、一次处理、一次检查备份，看作业栏的运行、完成和收起，以及状态栏文字。
4. 打开 `?missing`，确认处理线、命令栏、活动栏、状态栏和工具页都显示缺依赖。
5. 用 Tab 键走一遍当前页面，焦点可见且顺序合理；试 `Ctrl+1`–`4` 与 `Ctrl+S`。
6. 在原生窗口中拖动标题栏、双击最大化、最小化、关闭，并从窗口边缘调整大小。
7. 新增的颜色、字号、间距都来自令牌；新增的文字符合词汇表。

## 不采用的方向

以下方向被考虑后否决，后续调整不要回到这些做法：

- **网页式页头与页脚**：系统标题栏下再放一条“产品名 + 标签”的顶栏，运行按钮放在页面底部。这是 1.0.0 之后一轮设计的做法，看起来像一个被装进窗口的网站。
- **阅读版式**：24px 标题、1.6 行距、38px 控件和 720px 文章宽度适合文档，不适合反复操作的工具。
- **网页字体**：打包 IBM Plex 让界面与系统其他软件不一致，还增加了分发时的字体许可义务。
- **卡片堆叠**：把每个设置区做成同样圆角、同样阴影的卡片从上到下长滚动。分组面板可以用，但只在内容区内、没有阴影，并且由处理线决定当前显示哪一组。
- **品红棋盘格（“丢失贴图”）标记**：小尺寸下只是一块杂色马赛克，看不出含义，也与线条图标不协调，已换成缺件图标。
- **三态循环的外观按钮**（跟随系统 → 浅色 → 深色）：系统为浅色时从浅色切到深色要点两次。
- **品牌绿色主色**：与“成功”状态冲突。品牌绿只留在标题栏的应用图标上。
- **全大写英文眉标**（WORKSPACE、PROCESSING 等）：对中文用户没有信息量。
- **暖米色底配陶土色、黑底配荧光色**：这是生成式界面的常见默认风格，与工具软件的气质无关。
- **手机宽度适配**：窗口最小 840px，移动端布局只会增加维护成本。

## 音频结果约定

沿用处理线参数编辑与全局作业栏。纯分析摘要注明不写素材；增益和归一化默认另存，无备份覆盖不可执行。作业结束后用可折叠测量明细展示输入/输出 LUFS、真峰值和实际增益，明确区分无法测量、未达目标和未提交，不用成功颜色掩盖这些状态。明细最多 100 条，完整报告可打开；紧凑窗口内换行、作业栏滚动。

## 存储维护交互

工具页使用默认折叠面板，沿用现有色彩和表格令牌。保留天数、预览、勾选清单、清理按钮按顺序排列；默认 30 天且不自动勾选。受保护记录同时显示原因，不能只用颜色表示；清理按钮展示选择数量。表格限高独立滚动，窄窗口允许 ID 和说明换行，不能引入横向溢出。翻页清空选择、修改天数清空预览，执行中禁用表单并显示“正在维护存储”；错误不自动重试删除。完整边界见[存储维护](../architecture/storage.md)。
