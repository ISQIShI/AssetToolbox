# ADR 0008：只读操作与安全音频处理

日期：2026-11-10。状态：已采用；补充 [0003](0003-processing-contract.md) 与 [0007](0007-operation-adapters.md)。

## 背景

音频测量不产生新素材，不能伪造转换输出或在另存模式复制全部文件。增益和响度统一需要明确保留原文件、峰值策略与有损重编码代价。同一提供方应复用工具依赖并分别适配各操作。

## 决策

- 目录 API 升至 3；操作 API 2 增加 `observe` 验收策略与 `preserveOriginal` 声明。既有 API 1 的两种转换策略继续有效，但不能使用新字段/策略；其他 API 版本拒绝。提供方 API 2、资源类型 API 1 不变。
- observe 只返回 metadata，禁止输出或 skipped；引擎核对临时输入未变且没有预期输出。仅观察的文件不写素材、备份或 intent；任务与结果仍可审计。混合流水线中观察当前阶段输入，后续失败统一回滚。
- 音频增益与归一化声明 preserveOriginal，默认另存；覆盖必须备份。配置 /2、任务和报告外层 /1 的结构不变，步骤照常锁定四项版本，不迁移旧配置或旧快照。
- 采用 FFmpeg 9.0.2 的 ebur128 测量和 volume 固定增益；不用 loudnorm 的动态回退，也不自动添加 limiter/compressor。超峰整体限制或失败，编码后复测。无法达到目标必须说明。
- FFmpeg 三个 adapters 各有版本与 schema，共享探测/编码实现。仅支持明确列出的编码和单/双声道；不开放任意命令或滤镜。
- 使用已有 Gyan essentials 本地工具，仅手动安装。大体积 ZIP/7z 尚不符合现有受限自动安装器能力，不为本功能削弱来源、摘要及解包约束。记录 GPLv3、源提交、构建参数和本地摘要，二进制不进入源码仓库。

## 代价与替代

测量加输出复测会增加耗时；短音效、静音和低响度内容不能可靠归一化。有损输出与元数据移除须显式提示。动态压缩可以更接近响度目标，但会改变动态，若以后添加，应成为用户主动选择的独立操作。分析仍使用现有任务系统，暂不新增媒体库或交互波形编辑器。
