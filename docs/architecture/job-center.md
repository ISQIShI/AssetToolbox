# 统一作业中心与入口冲突

状态：作业中心已实现；本文调度方案仅为设计比较，排队和并行尚未实现。

## 当前桌面行为

活动栏“作业”（Ctrl+5）查看当前安装下桌面、CLI、stdio MCP、HTTP 和 MCP HTTP 的持久作业。列表每页 20 项，每 2 秒刷新；搜索和运行/结束筛选仅作用于本页。选中后读取进度、错误、50 项一页的文件/恢复预览明细，可打开完整报告或进入关联素材任务。重启后重新打开作业中心即可查询历史记录。

源码为 `desktop/src/core/job-center.ts`、`views/JobsView.vue`。全部调用现有 jobs/status/results/cancel，不增加业务接口，应用/response /3、job/2 保持不变。每次读取及显式取消仍由 ApplicationService 授权。已有 job/2 没有可靠的提交入口标签，界面不猜测来源；显示持久 ID、操作和创建时间。

观察状态与 workbench 的本会话 ActiveJob 分开；选择作业不调用 submit，也不接管生命周期。离开页面停止刷新，关闭纯观察窗口不取消其他入口作业；本窗口自己提交的运行作业仍按原规则安全取消。取消按钮只取消明确选中的 ID，并继续等待权威 done。清理过的记录保留摘要并显示明细过期；更换选择时丢弃旧异步结果。

当前列表分页仍由核心扫描持久目录；每页状态逐项读取。未提供全局状态过滤、队列、自动重连运行或后台常驻服务。文件名与结果文案只作为文本显示。音频完整测量可从报告读取。

## 不同入口是否冲突

会争用资源，但同一安装已有保护，不会因此同时写同一批素材：

1. submission 锁串行化提交和幂等登记；同会话已有活动作业时，submit 直接返回 BUSY。
2. 跨会话可以各自登记 jobId；batch 与依赖 worker 启动后竞争同一 installation execution 锁，未取得者最终以 BUSY 失败。调用方收到 submit 成功不代表处理成功，必须查看最终状态。
3. 任务锁、逐文件哈希和提交校验继续保护续跑/恢复；存储清理也取得提交和执行锁。查询不取得执行锁，允许并行观察。
4. 同安装不同目录也串行；不同安装的执行锁不同，不能保证它们不会操作相同路径。现有哈希/排他写入会拒绝部分冲突，但不是跨安装事务保证。

代码依据：`application/service.js` 的 submit、`application/lock.js`、`batch.js`、依赖 worker。已有 application 测试实际验证外部处理占锁时，桌面预览生成的作业以 BUSY 结束；unified/http 测试验证观察者关闭、服务停止和显式跨入口取消。

## 调度方案比较

| 方案 | 收益 | 成本与边界 |
| --- | --- | --- |
| 保留串行，提交时统一拒绝 | 改动小，更早明确 BUSY，避免生成注定失败的作业 | 必须把提交预留与 worker 接管锁做成一致协议，单纯先查锁有竞态；用户仍需重提 |
| 持久串行队列（建议下一阶段） | 所有入口按同一顺序执行，消除正常争用失败；保持现有文件处理安全边界 | 需要唯一调度者、持久 queued/claimed/running 状态、崩溃恢复和等待取消；GUI/stdio 退出后的队列所有权必须明确 |
| 直接并行 | 无依赖作业吞吐可提高 | 当前同步引擎及大编码器会竞争 CPU/内存；移除全局锁会引入目录重叠、覆盖、恢复和依赖切换竞态，不建议直接采用 |
| 队列＋按资源加锁的有限并行 | 不相交目录可并行，兼顾吞吐和安全 | 需要源/目标/备份/任务/依赖的读写资源声明、父子目录重叠检测、规范路径和别名处理、有序加锁、并发预算；工程成本最高 |

建议先实施**单安装持久 FIFO 队列，执行并发度 1**，验证稳定后再允许互不冲突的任务有限并行。只读分析也会消耗工具资源且源文件可能被修改，不能仅按 observe 标签直接绕过锁。

## 推荐队列契约草案（未实现）

- 启动上下文声明所有者及 connection/server 生命周期；关闭观察者不影响队列。本会话正常退出取消自己等待中的作业、对运行项请求文件边界取消；需要断连后继续的任务必须由显式常驻服务拥有，不能悄悄改变 stdio/桌面行为。
- 提交在同一事务边界写入幂等身份、规范化请求和队列序号。统一调度者持有安装级租约；claim/心跳/完成持久化，worker 未确认退出不得重复派发。重启以任务日志和进程身份核对，不能盲目重跑。
- 出队时重新核验目录授权、路径链接、适配器版本、依赖和恢复选择哈希。排队期间用户修改文件导致冲突时明确失败，不能自动扩大恢复范围。
- 取消 queued 项无需启动 worker；运行取消沿用文件边界。配置队列上限和饥饿保护，CLI 等待与 HTTP 查询提供 queued 状态和位置；为会话等待设置显式超时策略。
- 新状态与持久队列格式必须独立升级契约并明确拒绝旧版本；不能将 queued 伪装为 processing。验收包括多入口同时提交、重复幂等、退出/强杀、claim 后崩溃、依赖更新、恢复和清理竞争。

并行方案还需以规范目录和任务 ID 声明读/写集合，冲突定义包含父子目录、别名和备份重叠；依赖安装/存储清理先作为排他维护屏障。多个安装共享素材时，建议由同一服务集中派发；跨安装全局锁方案需另行设计。
