# 统一作业中心与入口冲突

状态：作业中心与单安装持久 FIFO 已实现，执行并发度 1；有限并行尚未实现。完整契约见[持久串行队列](queue.md)。

## 桌面行为

活动栏“作业”（Ctrl+5）查看桌面、CLI、stdio MCP、HTTP 和 MCP HTTP 的持久作业。每页 20 项、每 2 秒刷新，支持本页 ID/操作搜索及排队/运行/结束筛选。选中后查看进度、队列位置、错误和每页 50 项的文件/恢复明细，可打开报告或进入素材任务。重启后重新打开作业中心即可查询。

JobsView.vue、core/job-center.ts 复用公共 jobs/status/results/cancel，当前应用/response /4、job/3。job/3 记录持有者 UUID，但没有可靠的提交入口标签，界面不猜来源。音频完整测量可从报告读取。

观察状态与本会话 ActiveJob 分开：选择不提交、不接管，离开页面只停止刷新。关闭纯观察窗口不取消别人作业；本会话退出取消自己的等待项和运行项。显式取消仅针对所选 ID；等待项不启动 worker，运行项等文件边界退出。读取失败清除旧状态和结果，切换选择丢弃旧响应，清理后提示明细过期。

## 当前冲突处理

原实现跨会话可先登记 jobId，再因执行锁冲突以 BUSY 失败。本轮改为提交锁内登记持久序号，由队首原持有会话串行启动；同会话也可提交多项。短暂提交锁争用由公共响应层最多等待 5 秒，队列满（100 个未结束作业）或会话退出明确拒绝。提交成功只表示已登记，必须查询最终状态。

全局执行锁、任务锁、逐文件哈希和恢复选择继续保护；确认前一 worker 退出才开始下一项。扫描、只读分析、恢复和依赖安装均排队。存储维护遇到等待/运行项拒绝清理。不同安装锁独立，仍不保证它们不会争用相同素材目录。

## 方案比较与后续

| 方案 | 收益 | 成本与边界 | 状态 |
| --- | --- | --- | --- |
| 提交时统一拒绝 | 改动小、早报 BUSY | 用户仍需重提；预检查与启动要避免竞态 | 未选择 |
| 持久串行 FIFO | 正常争用变成等待；沿用文件安全边界 | 依赖原持有会话；同步扫描尚无索引 | 已实现 |
| 直接并行 | 可能提高吞吐 | CPU/内存竞争，目录重叠、恢复和依赖切换冲突；不可直接移除锁 | 不建议 |
| 队列＋资源锁有限并行 | 不相交任务并行 | 需声明源/目标/备份/任务/依赖读写集合，识别父子目录、链接别名，设置并发预算 | 后续评估 |

当前队列不是后台守护服务：HTTP 由服务进程持有，connection 入口退出时取消自己作业；崩溃会话不自动接管。需要应用全关后继续执行时，应先实现明确的常驻服务所有权及租约，不能悄悄改变 stdio/桌面生命周期。

下一阶段优先优化历史目录索引和位置查询成本，再考虑后台服务。有限并行需有序加锁、饥饿保护、维护屏障及崩溃测试；只读分析也会消耗编码器并与源文件修改竞争，不能仅凭 observe 标签绕过锁。多个安装共享素材时，优先由一个服务集中派发。
