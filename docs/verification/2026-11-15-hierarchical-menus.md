# 三级步骤选择与多级菜单验收

日期：2026-11-15。基线 `10b4933`。本轮调整桌面选择交互，核心、协议、任务与过滤表达式格式不变，也没有新增依赖。

## 实现范围

- 添加步骤依次选择资源分组、格式、操作；只有末级操作创建步骤。支持当前层搜索、路径、逐级返回、方向键、Esc 和焦点归还。仍按目录生成有效组合，缺依赖的组合可配置。
- `SelectBox` 支持递归分组，已有 Reka UI 提供子菜单行为。过滤属性按通用文件/图片属性分层，过滤格式值和步骤格式按类别分层；短列表保持单层。
- 分支不提交值，叶子沿用原核心 ID；目录外过滤值仍可见。步骤只列出适用属性，忙碌禁用传递到浮层；没有更改处理、备份和恢复规则。

原生测试发现 DropdownMenuTrigger 的内部 ID 覆盖了字段 ID，导致标签关联失效。封装改用 `as-child` 的明确按钮，菜单关联同一 ID，并增加组件断言。截图还发现紧凑表单的属性字段未独占一行，已改为深度选择器并增加行位置断言。修正后重新构建 EXE。

菜单测试辅助同步修正：等待实际条目而非即时枚举；不依赖子菜单挂载前为空的 `aria-controls`；分支与叶子分别定位，避免重试点击转向分支。向左翻转时，以连续鼠标移动进入子菜单，避免一次跳过相邻分支破坏悬停方向判断。保留真实点击、键盘、文件结果和原素材字节断言。

最终 EXE 为 9,119,232 字节，SHA-256 `939892289966c1851459d389691751af3a515fedd0b5fd83859e6c8c7d6499bf`，只留本地。
