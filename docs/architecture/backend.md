# 后端与框架设计

后端由 Rust 原生宿主和多个本地 Node 进程组成。Rust 不执行压缩算法；文件扫描、配置、任务日志、压缩与恢复全部位于 `resCompress/`。流程的主要目标是隔离阻塞编码器、保留原文件并支持中断后的安全继续。

## 原生宿主

`desktop/src-tauri/src/main.rs` 的 `tool_root()` 优先从 EXE 目录定位核心，调试时可回退到源码根目录。`Bridge::start()` 启动随附 Node 和 `desktop-bridge.js`，隐藏子进程窗口，以管道通信。

`core_call` 在 `spawn_blocking` 中持有会话互斥锁，按序发送带递增 ID 的 JSON 并读取对应响应；ID 不匹配、EOF 或错误字段均返回前端错误。桥接进程按需启动，已退出的实例会报错，当前没有自动重连/自动重放请求。

`open_report` 先向桥接层索取当前作业已完成的报告目录，再调用 Explorer。Tauri capability 只配置必要窗口操作与目录选择，CSP 约束页面资源；没有通用 shell API。测试端口必须由 `RESOURCE_COMPRESSOR_TEST_PORT` 显式启用。

## 桌面桥接与作业编排

`desktop-bridge.js` 的 `DesktopBridge` 保存一个当前作业，拒绝并发启动。每次在系统临时目录生成 `resource-desktop-*`，排他写入请求，启动独立 `batch.js`。工作进程 stderr 最多保留末尾 8000 字符用于失败诊断。

`poll()` 尝试读取原子替换的 `status.json`，遇到短暂文件占用保留上次状态。即使状态文件已经写出 `done: true`，进程尚未退出时仍返回 `done: false`。进程已退出而状态未完成则报告异常结束。

`cancel()` 写标记文件，不终止编码器。stdin 关闭、SIGTERM 或每 1500 ms 的父进程存活检查触发 `shutdown()`：请求取消、等待工作进程、清理临时目录。强制终止整棵进程树仍可能打断提交，需依赖持久日志恢复。

`batch.js` 的 `runJob()` 统一分派请求，按约 150 ms 节流写状态；重要节点强制写入。状态先写 `status.next` 再 rename，Windows 短暂占用有有限重试。作业持锁运行，在 `finally` 解锁；持久化失败停止后续处理。报告写失败单独返回 `reportWarning`，不撤销已提交素材。

## 压缩流水线

`compress.js` 导出 `collectResources`、兼容旧接口的 `collectImages`、`prepareFolder`、`scanFolder` 和 `compressFolder`。

1. **规范化与扫描**：校验模块参数；解析真实根路径；另存与覆盖备份互斥。目标不能等于源目录或成为源目录祖先；允许源目录内的输出/备份，但扫描时排除。遍历忽略链接，扩展名不区分大小写，结果排序。
2. **只读预览**：统计数量/字节、启用状态、输出冲突和缺少工具；问题文字最多 30 条。预览不验证内容、不调用编码器、不创建素材输出，也不承诺压缩率。桌面预览仍有临时状态文件。
3. **准备工具**：仅为实际需要的启用模块检查 EXE，在临时工作目录准备编码器。JPG-C 复制到临时目录，隔离其日志。
4. **逐文件编码**：重新检查路径，读原字节，验证格式，在临时输入/输出上调用适配器。输出必须通过格式检查且更小，否则保留原内容。当前 PNG/JPG 验证主要检查文件头，MP3 检查帧特征，并非完整解码器。
5. **提交前记录**：重新确认源内容未变，计算 SHA-256；批处理通过 `beforeCommit` 刷盘写入 intent，再进入输出/备份/替换。
6. **提交文件**：新输出使用 `wx` 排他创建；替换在同目录写临时文件、fsync、复核原内容后 rename。覆盖模式仅为真正变小的文件建立原始备份。
7. **记录结果**：`onFile` 写结果日志，状态为 `compressed`、`skipped` 或 `failed`，然后处理下一文件。取消只在文件边界检查。

编码失败时覆盖模式保留原文件；另存模式在可写时复制原文件，仍计为失败。禁用的已知格式在另存模式原样复制；未知扩展名不在扫描清单中，不会作为普通文件自动复制。备份写入失败阻止覆盖；替换失败时撤销本次新建且尚未生效的备份。

## 模块框架

`compressors/index.js` 扫描直接子目录，忽略 `_`、`.` 开头目录和链接目录；无入口文件的普通目录忽略，只有一个入口文件的不完整模块报错。排序按 `order` 再按 ID；扩展名和参数名冲突会停止加载。

`schema.js` 编译 `config.js`，统一默认值、字段类型、范围、精度、保留名称和自定义校验。`options.js` 聚合 `FIELDS/DEFAULTS/LIMITS`，将 camelCase 转为 CLI 参数，并严格解析模块参数对象。

适配器必须提供 `validate(data)`、`compress(context)`，可选 `prepare`、`shouldCompress`、`executableName`。只操作上下文提供的临时文件，不自行写用户目录或启动脱离任务的后台进程。接口与字段详见[模块开发说明](../../resCompress/compressors/README.md)。

| 模块 | 编码器与默认行为 |
| --- | --- |
| PNG | pngquant，速度 3、质量 50–80；退出码 98/99 视为无需替换 |
| JPG/JPEG | JPG-C，质量 5；质量 0 直接跳过；同时检查退出码与错误日志 |
| MP3 | LAME，默认关闭，启用后 ABR 24 kbps；编码结果仍需比原文件小 |

模块自动发现只在进程加载时发生，无热更新；变更模块后需重启应用。恢复代码不依赖模块加载，因此移除编码器后仍可恢复已有备份。

## 续压与重试

`batch.js` 完整扫描后写一次 plan；扫描中取消时清单未固定，继续会重新扫描。`resume` 只选 pending，`retry` 只选 failed，均使用原任务路径与参数。成功项和计划完成后新增文件不会混入旧任务。

继续前验证根路径、模块归属及 pending 文件的大小、mtime/ctime。变化项安全失败，显式重试才接受当前源版本。另存失败副本只有在其哈希仍匹配任务记录时才允许替换；已有其他文件和被用户改写的副本始终保留。崩溃窗口的判断见[持久化](persistence.md)。

## 备份恢复

`restore.js` 从卷根逐级检查链接与目录类型。任务恢复核验备份的原始 SHA-256，目标必须缺失、等于备份，或仍匹配该次压缩结果；其他内容判定冲突。写临时文件后再次核对双方，再替换目标。缺失目标优先硬链接创建，文件系统不支持时退回 `wx`，避免覆盖竞争期间出现的文件。

显式 selection 带预览哈希，预览后变化会失败；已经等于备份则安全跳过。开始实际恢复前写 `restore-start`，此后旧任务禁止续压/压缩重试。空选择、提前取消或根路径检查失败不会启动恢复。已恢复成功项不会因后来改动被旧任务再次覆盖。

无任务的旧备份可按完整目录导出，包含任意格式；目标同内容跳过、不同内容冲突，不建立持久任务。所有恢复均保留备份，不删除新增文件，也不还原文件时间戳等完整文件系统元数据。

## 安全边界与验证

文件系统校验和哈希可防常见冲突，但检查与提交之间并非跨进程事务锁；不同任务不应同时操作同一批素材。多文件配置保存有出错回滚，不等于断电原子事务。外部编码器无超时，卡住时安全取消仍需等待当前工具返回。

对应测试位于 `resCompress/tests/`：`compress`/`resources` 覆盖真实编码器，`discovery`/`layout` 覆盖模块与配置，`batch`/`desktop` 覆盖进程协议与取消，`resume`/`restore`/`restore-preview` 覆盖日志、锁、崩溃窗口和文件保护。
