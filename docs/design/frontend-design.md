# 前端设计规范

状态：已采用。日期：2026-11-09。适用范围：`desktop/src/` 的全部界面工作，包括新增页面、组件、字段类型和文案。

本文是界面设计的唯一规范来源：视觉主张、令牌、布局、组件、状态和文案规则都以这里为准。组件职责、状态流转和请求映射等实现细节见[前端架构](../architecture/frontend.md)；与旧界面不兼容的原因见 [ADR 0004](../decisions/0004-frontend-redesign.md)。令牌的实际取值以 `desktop/src/styles/tokens.css` 为准，本文表格与其同步维护。

## 设计主张

- **产品**：本地资源处理工具。素材文件夹按顺序经过若干步骤（缩放、压缩），写回原处或另存，并且可以续跑和恢复。
- **使用者**：游戏开发者和技术美术。熟悉“贴图”“图集”“音频循环”这些概念，处理的是成百上千个文件的文件夹，在意每一步做了什么、文件是否安全。
- **主要任务**：配置一条处理线并运行；运行中随时能看到进度并取消；出问题后继续、重试或恢复。

界面应当像一台**工作台**：克制、精确、可预期。它不是营销页面，没有首屏，也不需要讨好。

### 核心隐喻：处理线

处理页左侧的竖线是整个界面唯一的强调元素。文件从“来源”出发，自上而下经过编号的步骤，最后到达“写入”。编号就是执行顺序，这是界面上唯一允许使用序号的地方，因为内容本身确实是一个序列。

```
■ 来源            UI
│
① PNG 图片缩放     Sharp / libvips
│
② PNG 压缩        ▦ 缺少依赖          ← 品红棋盘格：缺少依赖
┊
③ JPEG 压缩       已停用              ← 空心节点 + 虚线：停用
│
④ MP3 压缩        LAME 4.0
│
⊕ 添加步骤
│
■ 覆盖原文件       备份到 Backups
│
□ 扫描结果        538 个文件          ← 仅在扫描后出现
```

选中的站点背景变为白色，与右侧编辑区连成一体，像一张从处理线上抽出的卡片。

### 设计原则

1. **处理线是骨架**：所有和“怎么处理”有关的设置都挂在处理线的某个站点上。不要在处理线之外另开设置区。
2. **颜色只表达状态**：中性色负责结构，彩色只出现在成功、警告、失败、缺依赖和焦点上。装饰性的彩色、渐变和色块一律不用。
3. **路径和哈希用等宽字体**：它们是需要逐字核对的数据。其他文字一律用正文字体，小标签也不例外。
4. **作业全局可见**：同一时间只有一个作业。它在窗口底部的作业栏中显示，任何页面都能看到进度并取消。
5. **结构即信息**：边框、分隔线、粗细变化都要表达层级或分组。分不清它表达什么的线就删掉。

## 令牌

所有颜色、字号、间距都通过 CSS 变量引用。组件样式里不写裸色值；需要新颜色时先在 `tokens.css` 增加令牌并更新本表。

### 颜色

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--canvas` | `#e6e9ed` | 窗口底色：顶栏、处理线、任务列表、运行栏。冷灰机壳 |
| `--paper` | `#ffffff` | 工作面：编辑区、输入框、选中的站点和行 |
| `--paper-sunk` | `#f3f5f7` | 表头、停用控件、提示条底色 |
| `--ink` | `#1f2531` | 正文、主按钮、处理线、选中标签 |
| `--ink-raised` | `#333b4b` | 主按钮悬停 |
| `--ink-2` | `#545d6e` | 次要文字、说明 |
| `--ink-3` | `#7d8697` | 占位、停用、虚线 |
| `--rule` / `--rule-soft` | `#c9cfd8` / `#dde1e7` | 控件边框、分区线 / 表格行线 |
| `--focus` / `--focus-wash` | `#2b50d8` / `#e8edfc` | 键盘焦点、链接 / 已勾选行 |
| `--ok` / `--ok-wash` | `#17704b` / `#e4f2eb` | 成功、节省体积、已完成 |
| `--warn` / `--warn-wash` | `#87540b` / `#f8efdf` | 可继续、已取消、结果过期、不完整 |
| `--danger` / `--danger-wash` | `#b8322b` / `#f8e6e4` | 失败、冲突、错误、删除 |
| `--missing` / `--missing-wash` | `#a80c97` / `#fae5f7` | 缺少依赖。取自游戏引擎“丢失贴图”的品红 |

主按钮使用墨色实心，不使用品牌色。界面没有品牌色，这是有意的。

### 缺少依赖标记

`.missing-swatch` 是 12px 的品红与墨色棋盘格，即游戏引擎里贴图丢失时显示的图案。它只能表示“处理工具缺少依赖”，出现在顶栏“工具”标签、处理线站点、步骤编辑器提示和工具页中。不要把它用于其他错误。

### 字体

| 角色 | 字体栈 | 说明 |
| --- | --- | --- |
| 正文与标题 | `IBM Plex Sans` → `Microsoft YaHei UI` | Plex 负责拉丁字母和数字，中文回退到系统雅黑 UI |
| 路径、哈希、扩展名 | `IBM Plex Mono` → `Consolas` | 只用于需要逐字核对的数据 |

IBM Plex 通过 `@fontsource/ibm-plex-sans` 与 `@fontsource/ibm-plex-mono`（OFL-1.1，锁定 5.3.0）打包进前端产物，只引入 latin 子集的 400/500/600 字重（等宽只用 400），满足 CSP `font-src 'self'`。不要引入在线字体，也不要打包中文字体。

全局开启 `font-variant-numeric: tabular-nums`，让进度、计数和体积对齐。

### 字号

取自经典排版比例，只用这六级：

| 令牌 | 大小 | 用途 |
| --- | --- | --- |
| `--t-small` | 12px | 提示、范围说明、计数、表头 |
| `--t-body` | 14px | 正文、控件、站点标题；行高 1.6 |
| `--t-lead` | 16px | 顶栏产品名 |
| `--t-title` | 18px | 作业栏标题与计数、任务图例数字 |
| `--t-heading` | 24px | 编辑区标题、扫描数字 |
| `--t-display` | 36px | 预留，当前未使用 |

字重只用 400、500、600。标题 600，标签和按钮 500。不使用斜体、全大写和字间距放大的小标签。

### 间距、圆角与尺寸

- 间距：`--s-1` 到 `--s-7` 对应 4、8、12、16、24、32、48px，全部为 4 的倍数。
- 圆角按层级：控件 4px（`--r-control`），浮层 6px（`--r-float`），处理线节点为圆形，区域和分栏不加圆角。
- 处理线宽 `--rail-width: 272px`；顶栏高 `--bar-height: 52px`；编辑区正文最大宽度 `--measure: 720px`，约 50 个汉字。
- 普通控件高 `--control-height: 38px`；编辑区边距 `--pane-padding: 32px`，窗口不超过 1000px 时为 24px，低于 760px 时为 16px。1000px 以内处理线收窄到 248px，给参数留出空间。

## 布局

### 窗口骨架

```
┌───────────────────────────────────────────────────────────────┐
│ 资源工具箱   处理  任务 3  恢复  工具 ▦1                       │ 顶栏 52px，canvas
├───────────────────────────────────────────────────────────────┤
│ 提示条（错误 / 成功 / 警告，按需出现）                          │
├──────────────┬────────────────────────────────────────────────┤
│ 列表或处理线  │ 编辑区（paper，左对齐，最大宽度 720px）          │
│ canvas       │                                                │
│ 272–320px    │                                                │
├──────────────┴────────────────────────────────────────────────┤
│ 运行栏（处理页空闲时）或作业栏（有作业时，任何页面）              │
└───────────────────────────────────────────────────────────────┘
```

- 外壳是纵向 flex：顶栏、提示、工作区、作业栏。**不要改用 CSS Grid 的固定行模板**：提示条和作业栏按需出现，Grid 自动放置会把工作区挤进错误的行。
- 工作区占满剩余高度，各分栏自己滚动，窗口本身不滚动。
- 所有内容左对齐。只有数字列右对齐。

### 工作区

| 标签 | 左栏 | 右侧 | 底部 |
| --- | --- | --- | --- |
| 处理 | 处理线（来源 → 步骤 → 写入 → 扫描结果） | 选中站点的编辑器 | 运行栏：步骤统计、保存配置、扫描预览、开始处理 |
| 任务 | 可搜索的任务列表，每行带进度条 | 任务详情：分段进度、路径、处理与恢复操作 | 作业栏 |
| 恢复 | 无；顶部是来源选择（任务的备份 / 独立备份文件夹） | 检查结果表：状态筛选、搜索、勾选、分页 | 表格内的恢复操作 |
| 工具 | 无；单栏，最大宽度 860px | 处理工具列表（缺依赖的排在最前并展开）、识别的资源类型、核心目录 | 作业栏 |

### 窗口尺寸

- 原生窗口默认 1220×850，最小 840×620。最小尺寸下不能出现横向滚动，E2E 会检查。
- 宽度低于 760px（仅浏览器调试时会出现）时，左栏移到上方，处理线最多占 28vh；运行按钮独立一行。560px 以内顶栏产品名与导航分行。
- 表单按编辑区容器宽度调整：步骤组合在 600px 以内变为两列，处理工具独占一行，360px 以内单列；写入方式在 600px 以内纵向排列。参数保持两列，宽高成对，420px 以内单列；独立参数占满一行。

## 组件

### 按钮

| 类 | 外观 | 用途 |
| --- | --- | --- |
| `.button` | 白底线框 | 普通操作 |
| `.button.primary` | 墨色实心 | 每个区域最多一个，表示下一步最该做的事 |
| `.button.quiet` | 无边框文字 | 关闭、次要退出 |
| `.button.danger` | 红色文字线框 | 删除步骤等破坏性操作，放在操作行最右侧 |
| `.button.small` | 28px 高 | 表格工具栏、分页 |

按钮文字说清楚会发生什么，不加箭头或图标。停用的按钮要能从周围文字看出原因，例如运行栏会写出哪一步缺少依赖。

### 表单

- 字段结构固定为“标签在上、控件、提示在下”（`.field > .label / 控件 / .hint`）。
- 每个控件都必须有关联的 `<label for>`，ID 用 `useId()` 生成，不能用标签文字拼 ID。
- 路径一律用 `PathField`：等宽输入框加“选择…”按钮，可直接粘贴路径。
- 参数一律由 `ParameterFields` 按核心返回的字段描述渲染。数值字段的提示自动合成“范围 a–b”和扩展提供的 hint。
- 步骤组合用浅灰工作面分组，与下方操作参数区分；标题在前，步骤顺序作为标题下方的辅助信息。

### 处理线站点

- 端点（来源、写入）是 12px 实心方块；步骤是 24px 圆形编号；扫描结果是空心方块；添加步骤是虚线圆加号。
- 停用步骤：空心编号，该段竖线变为虚线，副标题写“已停用”。
- 缺少依赖：编号底色变为品红，副标题显示棋盘格和“缺少依赖”。
- 每个站点是一个按钮，选中时 `aria-current="true"`。端点带 `data-station`，步骤带 `data-step-id`，供测试定位。
- 处理线顶部固定显示标题和步骤总数；选中站点左侧增加墨色标线，连接线在白色选中背景上保持连续。添加菜单按 Esc 关闭后，焦点回到添加按钮。

### 运行栏与工具列表

- 运行栏同时显示启用步骤数与当前写入策略。点击写入摘要定位到“写入方式”；不备份时用警告文字明确提示。缺依赖时显示获取方式入口，直接进入工具页。
- 工具列表使用原生 `details/summary`，名称前有随展开状态旋转的折角标记；展开行使用浅灰底，依赖说明、获取入口和许可记录在下方分组显示。支持 Enter 和空格操作。
- 恢复页在紧凑窗口减少间距，文件表格独立滚动，优先保留筛选、勾选计数与恢复操作的位置。

### 作业栏

- 上边线就是进度条（3px，墨色）。总数未知时显示来回扫动的不确定进度，减少动态效果设置下停止动画。
- 运行中：标题、阶段、`已处理 / 总数`、耗时、当前文件（等宽、单行省略）、取消。
- 结束后：结论（已完成 / 完成，N 个失败 / 已取消 / 未完成），关键数字，打开报告、查看任务、关闭。
- 预览类作业（扫描预览、检查备份）成功拿到结果后自动收起，结果显示在所属页面；失败时保留作业栏显示错误。
- 关闭作业栏只隐藏界面，不删除任务和报告。

### 提示条

`.callout` 左侧 3px 色条加浅色底，按 `danger / warn / ok / missing` 区分。全局错误和成功提示显示在顶栏下方，可以关闭；局部提示放在对应内容上方。

### 表格

表头吸顶，用 `--paper-sunk` 底和小字号；行线用 `--rule-soft`；数字列右对齐且不换行。已勾选的行使用 `--focus-wash`。

## 状态语义

| 状态 | 颜色 | 出现位置 |
| --- | --- | --- |
| 已完成、可用、节省体积 | `--ok` | 任务状态、工具状态、体积变化为减少 |
| 可继续、已取消、结果过期、体积增大、检查不完整 | `--warn` | 任务状态、作业结论、扫描结果 |
| 失败、冲突、错误、无法读取 | `--danger` | 作业结论、恢复状态、任务状态 |
| 缺少依赖 | `--missing` 加棋盘格 | 工具标签、处理线、步骤提示、工具页、运行栏 |
| 中性（正在处理、已开始恢复、可恢复） | `--ink-2` | 其余状态 |

体积变化统一用 `sizeChange()` 格式化：节省显示为 `−2.0 KB`（绿色），增大显示为 `+100 B`（警告色）。不要直接显示 `savedBytes` 的原始符号。

## 文案

### 词汇表

界面用使用者的语言，架构文档用实现的语言。两者对应如下，新增界面文字时沿用左列：

| 界面用词 | 架构 / 协议术语 |
| --- | --- |
| 处理线、步骤 | pipeline、step |
| 资源类型 | resource type |
| 操作 | operation |
| 处理工具 | provider |
| 操作参数 / 工具参数 | `parameters` / `providerOptions` |
| 来源文件夹 | `sourceDir` / `folder` |
| 写入方式：覆盖原文件 / 另存到新文件夹 | `saveMode`: `overwrite` / `saveAs` |
| 替换前备份原文件 | `backupEnabled` |
| 扫描预览 | `preview` |
| 检查备份 | `restore-preview` / `restore-export-preview` |
| 任务的备份 / 独立备份文件夹 | 任务恢复 / `restore-export` |

### 动作名称一致

同一个动作从按钮到作业栏标题使用同一个名字：

| 按钮 | 作业栏标题 |
| --- | --- |
| 扫描预览 | 扫描预览 |
| 开始处理 | 处理资源 |
| 继续未完成 | 继续未完成 |
| 重试失败项 | 重试失败项 |
| 检查备份 / 检查独立备份 / 重新检查 | 检查备份 |
| 恢复所选 N 项 | 恢复所选文件 |

### 写法

- 用平实的动词和句子，句号结尾。不用感叹号，不道歉，不用“您”。
- 错误说清楚发生了什么、怎么办：“第 2 步的处理工具缺少依赖，安装或停用后才能开始处理。”
- 空状态说明这里会出现什么、怎样开始：“还没有任务。在“处理”页开始处理后，进度会保存在这里。”
- 计数写成句子或带单位的短语（“3 / 4 个步骤已启用”），不要用 `A · B · C` 拼接元数据。
- 不在标题上方加小标签，不用全大写英文标签，不用“WORD — 片段”式标题。

## 动效

只有两处主动动效：作业栏的进度条宽度过渡，以及总数未知时的扫动。其余变化都是对用户操作的直接响应，例如展开添加步骤菜单、切换站点，不加入场动画。`prefers-reduced-motion` 时全部动画缩短到近似为零。

## 可访问性底线

- 键盘可以到达所有操作，焦点统一显示 2px `--focus` 轮廓。
- 图标性元素（节点、棋盘格、色键）设 `aria-hidden`，含义由文字表达；只靠颜色区分的状态必须同时有文字。
- 文字与所在背景（paper、canvas、paper-sunk、focus-wash）的对比度不低于 4.5:1，状态色均已按 canvas 校验；`--ink-3`（约 3:1）只用于占位、停用和装饰线，不承载必须读到的信息。
- 作业栏是 `role="status"` 且 `aria-live="polite"`；全局错误是 `role="alert"`。

## 扩展界面的方式

- **新增资源类型、操作或处理工具**：不需要改前端。添加步骤菜单、步骤编辑器、工具页和识别类型表都由 `bootstrap` 返回的目录驱动。
- **新增参数字段类型**：在 `ParameterFields.vue` 增加分支，并在扩展契约中登记；保持“标签在上、提示在下”。
- **新增工作区**：在顶栏加标签，左栏 + 编辑区的主从结构优先；作业相关逻辑放进 `core/workbench.ts`，不要在视图里直接调用 `call('start')`。
- **新增作业类型**：在 `workbench.ts` 的 `JobKind` 中登记，并决定它是否属于“预览类”（结果在页面内显示、作业栏自动收起）。

## 在浏览器中调试界面

在 `desktop/` 执行 `npm run dev:web`，打开 `http://127.0.0.1:1420`。开发模式下检测不到 Tauri 时，`core/api.ts` 改用 `core/preview-core.ts` 模拟核心：生成样例配置、任务、扫描和恢复结果，并模拟作业进度。它不读写任何文件，生产构建会剔除。

| 地址参数 | 效果 |
| --- | --- |
| `?missing` | pngquant 显示为缺少依赖 |
| `?empty` | 没有任务 |
| `?duration=6000` | 模拟作业持续的毫秒数，默认 4000 |

模拟核心只用于看效果。行为验收以组件测试和原生 E2E 为准。

Vite 文件监听排除 `src-tauri/`，避免 Windows 原生构建锁定 EXE 时使浏览器预览报 `EBUSY` 并退出；前端源码热更新仍正常工作。

## 改动前后的核对清单

1. 在 1220×850 和 840×620 下截图，确认没有横向滚动、文字截断后仍可辨认。
2. 运行一次扫描、一次处理、一次检查备份，看作业栏的运行、完成和收起。
3. 打开 `?missing`，确认处理线、运行栏、顶栏和工具页都显示缺依赖。
4. 用 Tab 键走一遍当前页面，焦点可见且顺序合理。
5. 新增的颜色、字号、间距都来自令牌；新增的文字符合词汇表。

## 不采用的方向

以下方向在本次设计中被考虑后否决，后续调整不要回到这些做法：

- **卡片堆叠**：旧界面把每个设置区做成同样圆角、同样阴影的卡片，从上到下长滚动。步骤多时很难看清顺序，也看不出哪些设置属于同一层级。
- **品牌绿色主色**：颜色被用在装饰上，失败和成功的颜色因此不够突出。
- **全大写英文眉标**（WORKSPACE、PROCESSING 等）：对中文用户没有信息量。
- **暖米色底配陶土色、黑底配荧光色**：这是生成式界面的常见默认风格，与工作台的气质无关。
- **深色模式**：当前不提供。`index.html` 声明 `color-scheme: light`。如需添加，在 `tokens.css` 中按令牌重定义，不要在组件里写分支。
