# 统一作业中心与入口冲突

状态：作业中心、持久队列与有限并行均已实现。单安装可配置 1–8 个执行槽位（默认 2），冲突项按登记顺序等待。完整契约见[队列与有限并行](queue.md)。

## 桌面行为

活动栏“作业”（Ctrl+5）查看桌面、CLI、stdio MCP、HTTP 和 MCP HTTP 的持久作业。顶部显示运行/等待数量与并行配置；按核心分配的槽位编号，自上而下排列横向卡片，空闲槽位保留占位。作业运行期间编号不随其他项完成而移动，等待卡片独立排列。

每 2 秒刷新活动快照，不受历史分页影响；历史每页 20 项，隐藏已在槽位/等待区展示的重复项，支持本页 ID/操作搜索及失败/取消筛选。详情显示进度、登记顺位、等待原因、错误和每页 50 项结果，可取消、打开报告或进入素材任务。

并行配置只在全局空闲时可用；输入 1–8 或一键采用 CPU 保守建议，服务接受后刷新槽位。建议值不直接等于核心数，不自动启用；权限和锁竞争仍由服务重验，错误保留原预算。刷新失败时移除旧配置控件，避免误把旧快照当作可操作状态。

JobsView.vue、JobCard.vue、core/job-center.ts 复用公共 queue/scheduling-set/jobs/status/results/cancel；当前应用/响应 /8、job/6。登记顺位包含运行项，不表示启动顺序或预计时间。状态只显示资源冲突、较早等待项、容量或等待派发，不公开其他权限范围的素材路径。不可见的占用显示匿名卡位；没有可靠的入口标签，界面不猜来源。

观察状态与本会话 ActiveJob 分开：选择不提交、不接管，离开页面停止刷新。关闭纯观察窗口不取消别人作业；本会话退出取消自己的全部等待和运行项，原生宿主等待桥接退出后才结束。重复退出请求不会跳过等待。显式取消仅针对所选 ID；等待项不启动 worker，运行项等文件边界。读取失败清除旧结果，切换选择丢弃旧响应，清理后提示明细过期。

## 冲突判定与调度

源目录、输出、备份、任务及提供方构成核心推导的读写集合。读读可共享，目录父子关系和别名也参与冲突判定。整个集合一次授予，保留任务锁、逐文件哈希和恢复选择。

按序选择可运行项；与运行项或更早等待项冲突则等待，无关项可利用剩余槽位。每项 dispatch 先预约容量，worker 独立占用保护父进程崩溃窗口，退出确认前不释放预约。维护清理要求全局无等待/运行项及独占屏障。队列最多 100 个未结束作业；正常资源争用不会创建一个随后因抢锁失败的转换任务。

| 方案 | 收益 | 成本与边界 | 当前选择 |
| --- | --- | --- | --- |
| 提交时拒绝 | 简单、早报 BUSY | 需要反复重提 | 仅用于容量满等拒绝条件 |
| 严格串行 FIFO | 文件保护模型简单 | 无关资源也互相等待 | 原基线，已扩展 |
| 直接并行 | 吞吐可能提高 | 目录重叠、恢复和依赖切换不安全 | 不采用 |
| 队列＋资源锁有限并行 | 无冲突作业并行，冲突项公平等待 | 需要资源声明、启动预约、维护屏障及崩溃保护 | 已实现，默认 2 项，可配置 1–8 |

## 仍有的边界

队列由原会话共同调度，不是后台守护服务；HTTP 由服务进程持有，connection 入口退出取消自己作业。崩溃等待项不接管、不重放；素材任务显式续跑。

不同安装不共用资源锁；多个安装共享素材时优先由一个服务集中提交。外部编码器内部线程不受作业槽位精确限制。同步历史扫描尚无索引，后续可优化查询成本；后台持续执行、运行中自动调节预算、优先级或跨安装协调需独立设计。
