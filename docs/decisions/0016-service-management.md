# ADR 0016：统一服务管理与公共能力入口覆盖

状态：已采用。日期：2026-11-12。修订 [0011](0011-unified-application.md) 的公共能力范围和 [0010](0010-local-http.md) 的传输启动方式，保留本机认证、policy 和作业生命周期。

## 问题与决定

HTTP/MCP 可以手动启动，但核心缺少可供桌面与 Agent 使用的服务管理用例。新增五个 ApplicationService 动作：配置、状态、启动、停止、客户端配置。入口只适配；HTTP-only 与 MCP HTTP 共用核心传输启动器，MCP SDK 仍是独立可选包。

用户选择服务跟随启动入口退出。采用进程内监听器及安装级运行记录、实例化停止请求，不引入常驻守护进程。新服务使用独立的 policy/server 上下文持有作业；关闭启动入口安全停止，观察者不接管。

管理权限独立于素材目录授权：受信任本地操作者配置，policy/2 显式 allowServiceManagement 且与服务配置完全一致的 Agent 可管理，不能改大自身权限。policy 变化轮换令牌，响应不返回令牌。核心应用/响应升级 /7、HTTP /api/v7；持久 job/5 不改，不迁移旧 policy/1。

stdio 是宿主会话协议，桌面生成连接配置，由 Agent 宿主建立管道并启动；不提供空悬的桌面 stdio 进程。手动指定 policy/token 的传统前台入口保留，复用传输实现但不冒充受管理配置。

## 替代与代价

后台服务更适合退出后持续运行，但增加守护进程、升级与权限撤销管理，本轮按用户选择不采用。直接把所有桌面设置放进 HTTP 会扩大权限；采用专门的管理授权与等权校验。文件记录不提供多用户或抗同权限篡改隔离，PID 重用和坏记录保守处理。

今后扩展公共契约必须同时提供各入口访问及跨入口行为验收；窗口与主题等入口特有功能仍留在入口。具体动作、启动方式、失败语义和验收矩阵见[服务管理](../architecture/service-management.md)。
