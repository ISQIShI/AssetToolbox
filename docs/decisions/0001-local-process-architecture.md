# 0001 本地多进程与模块化核心

## 背景与约束

应用需在 Windows 上调用既有 PNG/JPG/MP3 编码器，支持中文路径、离线便携运行，并延续已有配置、备份和任务日志。编码器调用会阻塞，需要保持窗口可响应并允许安全取消。

## 当前采用的方案

- Vue 3/TypeScript 实现界面，Tauri 2/Rust 提供 WebView2 宿主和受限原生命令。
- Node 保留通用业务核心；Rust 通过 JSON Lines 管道调用桌面桥接进程。
- 每个作业使用独立 Node 工作进程执行同步编码器，状态与取消通过临时文件传递。
- 模块 schema 统一驱动参数界面、CLI、默认值与校验；编码器仅在临时文件上操作。
- 持久任务使用写前 intent、结果日志、SHA-256 和锁，支持中断后的核对与继续。

## 取舍

这一结构复用现有核心和格式，无需本机 HTTP 服务，编码器阻塞与界面事件循环隔离。代价是跨语言协议、双重任务生命周期、状态轮询，以及多个文件之间的一致性维护。

全部迁移到 Rust、引入本地 HTTP 服务或数据库均属于未来可评估的备选，不是当前实现。若未来采用，应提出新的决策并证明对便携部署、CLI、旧任务和恢复安全的兼容性。

## 维护与验证

不要绕过模块 schema 硬编码格式，不向前端开放任意命令执行，不强杀编码器实现普通取消，不以整批结束时一次保存替代逐文件日志。跨层变更同时验证 Node 核心、Vue 行为、release 构建和原生 WebView2 流程；文件安全断言保持独立可测。
