# ADR 0007：提供方按操作组织适配器

状态：已采用。日期：2026-11-10。

## 背景与约束

原契约允许 supports 声明多个操作，但提供方只有一个 execute 和一份专属参数 schema，执行上下文未传 operation。综合工具无法明确分派，切换同操作工具还会丢失公共参数。

保留三层业务边界、可信本地扩展、同步执行、提供方依赖管理和文件安全设施，不接入 Cordis。用户要求不保留旧接口兼容。

## 决定

提供方 API 升级为 2，adapters 按操作 ID 索引，每个适配器独立声明 version、resourceTypes、schema 和 execute。支持关系由注册器生成，目录 API 2 通过 adapters 数组输出各操作的字段；不再提供顶层 provider.fields。

引擎调用选中适配器，传入 operation、resourceType、公共 parameters 和专属 providerOptions。提供方统一管理来源、安装、检查及每作业一次的 prepare；适配器共享固定工具路径。只改一个适配器时升级该适配器版本，共同行为变化则升级提供方版本。

同操作切换工具保留公共参数，专属参数取目标适配器默认值；跨操作重置两组。保留步骤 ID 与启用状态，清除旧版本快照后重新规范化。

## 备选方案与取舍

- 在单一 execute 内 switch(operation)：分派可行，但无法自然隔离专属参数和版本，后续更容易误用字段。
- 每个“工具＋操作”注册为独立提供方：重复登记安装、许可与可用性，同一工具在前端重复出现。
- 按操作适配器：增加一个轻量结构，复用既有注册器和 schema 校验，无需引入插件生命周期框架。

当前适配器必须满足操作全部公共参数语义，不加入按工具裁剪参数范围的能力协商。内置功能范围不变；多操作和多提供方由隔离测试扩展验证。

## 影响与验证

配置 schema 升为 asset-toolbox.settings/2；拒绝 /1，不修改旧文件。步骤快照增加 versions.adapter，缺失或任何版本不匹配均拒绝处理、续跑和重试。任务/报告外层 schema 不变；既有备份恢复不依赖适配器，不迁移或执行旧快照。

修订 [ADR 0003](0003-processing-contract.md) 的提供方接口、版本与配置约定，其他安全边界保持。测试覆盖注册拒绝、参数与版本隔离、单次 prepare、按序分派、策略区别、失败回滚、前端字段与参数保留，原生 E2E 验证真实目录通信与多操作任务。实际结果见[项目状态](../project-status.md)，接口见[扩展契约](../architecture/extensions.md)。
