# 源码发布与二进制分发核对

当前授权范围：GitHub 公开源码仓库及源码 Release，项目自有代码 MIT。2026-11-15 用户明确要求将既有私有仓库转为 public 并发布首版；此前“仅私有”限制由此取代，第三方 EXE 留在本地的范围不变。Release 仅使用 GitHub 自动生成的源码归档，不上传完整便携包或二进制附件。标签触发、版本规则与发布门槛见[发布流程](releasing.md)。来源与许可事实集中于 [THIRD_PARTY_NOTICES](../THIRD_PARTY_NOTICES.md)，前端获取说明来自提供方 provenance.json。

## 源码发布条件

1. 提交根 LICENSE、包 license 元数据、第三方署名和可核验的来源/版本/哈希。
2. 当前树及将上传的全部可达历史都不得包含 EXE/DLL/.node、node_modules、个人 data、.local 或凭据；仅增加 .gitignore 不能移除历史 blob。
3. 核对远端全部分支/标签、可达历史及 Actions 日志/附件；如发现敏感内容，先在隔离副本处理并复核，不直接公开。既有历史已清除第三方二进制；不推送本地历史备份或全部 refs。
4. 执行 `node scripts/check-release.mjs --source`，检查源码与历史边界；另审查变更、敏感数据及 Git 暂存内容。
5. 确认目标为 `ISQIShI/AssetToolbox`、main 已通过 CI，完成上述检查后按授权将既有仓库设为 public。再推送明确的版本标签，由 CI 创建 Release；验证 private=false、MIT 识别、远端 HEAD、标签提交与 Release 资产范围。可见性与标签操作失败应明确处理，不能绕过发布门槛手工附带二进制。

当前发布策略不妨碍本地使用已安装工具。新克隆只需安装 Sharp npm 依赖即可使用缩放；其余工具通过前端官方获取页面和安装位置说明配置。缺依赖的启用步骤会禁用“开始处理”，可禁用该步骤继续其他功能；刷新只读检查，不丢失当前参数。

前端现可主动从原渠道下载固定核验版本的 LAME/Sharp，见[依赖管理](architecture/dependencies.md)。源码发布可以包含 URL 与摘要清单，不得包含 `data/dependencies/` 中下载或解包的文件；自动获取不解除下列再分发要求。

| 组件 | 发布前必须完成 |

| pngquant | 确认采用 GPL 分发还是已取得适用商业许可；附作者/原始代码声明、许可证、准确对应源码和构建脚本/依赖。官网通用链接不能自动替代对应源码提供义务。MIT 项目代码不应声称覆盖该 EXE。 |

| LAME + 解码 DLL | 核对 RareWares 实际构建与对应 LAME/mpg123 源码、补丁、链接方式、完整许可；保留署名及源码获取材料。当前 ZIP 只有二进制，缺少完整声明，尚不满足本项目放行条件。 |
| Sharp 原生包 | 保存包内 LICENSE 及组件版本表，补齐包内未附带的 LGPL 和其他组件完整声明，核对 LGPL 的对应源码、修改/替换/重新链接要求及其他组件声明；不要只保留 Sharp 主包 Apache 文本。 |
| Node / Tauri / 前端及 Rust 依赖 | 针对实际发布产物生成依赖清单、完整许可证/NOTICE 和适用源码义务；核对运行时版本与 Node 许可合集一致。 |

许可证关系依实际组合与分发方式判断，进程隔离并非自动豁免条件。当前结论是源码发布范围可以执行，完整便携包核对未完成；`--portable` 检查会明确失败，防止将本地构建误当成可对外发行包。

## 更新与验证

先在忽略的隔离目录下载/编译，核对 HTTPS 来源、真实版本、SHA-256 及许可，再备份并替换本地工具。提供方实现行为改变时升级 provider.version，旧任务不得悄悄改用新实现。不要覆盖用户素材或依赖外部镜像自动更新。

本次 pngquant 2.17.0 → 3.0.3、LAME 3.100.1 → 4.0，两个提供方契约版本升为 2.0.0；JPG-C、Sharp 保留。回归必须含真实编码/解码、损坏输入、备份/恢复、缺失工具与伴随 DLL、渠道显示、原生构建/E2E。具体结果见[项目状态](project-status.md)。
