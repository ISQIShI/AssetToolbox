# ADR 0019：处理页概览栏、不描边面板与窗口材质

状态：已采用；其中“窗口材质”一项已被 [ADR 0020](0020-activity-workspace-and-number-controls.md) 撤回（实机上框架色调与工作区不统一），`core/material.ts`、透明窗口配置与主题同步权限均已删除。其余决定仍然有效。日期：2026-11-15。

关联：[前端设计规范](../design/frontend-design.md)、[前端架构](../architecture/frontend.md)、[ADR 0006](0006-desktop-application-shell.md)、[ADR 0018](0018-headless-ui-primitives.md)、`desktop/src/components/RunInspector.vue`、`desktop/src/core/material.ts`。

## 背景与约束

ADR 0018 之后控件的外观和行为已经统一，但页面读起来仍像“带边框的网页表单”：

- 处理页的编辑区是一条靠左的窄表单，窗口右半边空着；用户最关心的“会处理哪些文件、处理得怎么样”没有固定位置。扫描结果是处理线末端的一个站点，扫描后会自动跳过去并打断正在编辑的步骤；处理进度和结果又在底部的作业栏。
- 每个分组、表格和信息条都画一圈 1px 边框，分量相同，没有主次。
- 每个区块下面常驻一两行解释，每个数字框下面常驻一行“范围 a–b”。
- 步骤编辑器里“上移、下移、恢复默认参数、删除步骤”单独占一行，与拖拽、右键菜单和快捷键重复。
- 窗口框架是一块纯色，与 Windows 11 上的其他软件不一致。

约束：不改变核心、协议、数据格式与权限；作业仍由 `ApplicationService` 的公共动作驱动，前端不新增作业路径；不放宽 CSP；组件测试与原生 E2E 的行为断言保持；最小窗口 840×620 下不能出现横向滚动。

## 决定

- **概览栏**：处理页改为三栏，右侧新增常驻的 `RunInspector`，显示当前作业、扫描数字和各资源格式的步骤数与文件数。原“来源”站点里的“会识别的资源”表并入这里。处理线不再有“扫描结果”站点，扫描不改变选中的站点。
- **作业只有一个组件、两种摆放**：`JobDock` 增加 `panel` 变体。处理页由概览栏渲染它，其他页面由 `App.vue` 在底部渲染，两处条件互斥。类名、`data-job-id`、`data-state` 与命令不变，测试与其他入口的约定不受影响。
- **窄窗口**：不超过 1040px 时概览栏移到处理页下方成为一条，只留作业与四个扫描数字；没有内容时不显示。不提高最小窗口尺寸。
- **不描边的面板**：分组面板、数据表外框、信息条改用 `--control` 底色加 `--shadow-card`（发丝线级别），内容面 `--surface` 略微加深以保持对比。圆角调整为 6 / 8 / 10px，页面标题新增 `--t-heading`（18px）。
- **说明不占版面**：过滤器的说明收进标题旁的 `Tip`；数值范围只在越界时作为错误提示出现；步骤命令改为标题行里只有图标的按钮。
- **来源落地区与拖入**：没有来源时显示整块可点的落地区；支持从资源管理器把文件夹拖进窗口。新增只读原生命令 `is_directory` 校验拖入的路径是文件夹；它不读取内容，也不经过核心。
- **窗口材质**：原生窗口声明为透明并请求 Mica。前端按 `navigator.userAgentData` 的 `platformVersion` 判断 Windows 11，只在支持时把 `--chrome` 设为透明；界面外观变化时用 `setTheme` 同步原生窗口主题。新增窗口权限 `core:window:allow-set-theme`。
- **动效**：页面切换只做新页面淡入，不做离场动画；站点切换与结果出现用 0.16 秒的上浮淡入。

明确不包含：任务、恢复、工具、作业页面的结构调整（另行处理）；滑块、数字步进、宽高锁定等新控件；更改默认主题或强调色。

## 备选方案

- **保留“扫描结果”站点，只把作业栏做大**：改动小，但结果仍分在两处，扫描仍会抢走选中项。
- **提高最小窗口宽度到 1000px 以上，概览栏始终在右侧**：布局只有一种，但小屏幕上无法缩小窗口；现有 E2E 也以 840×620 为紧凑基线。
- **为处理页另写一个作业组件**：可以完全按卡片设计，但状态、命令和文案要维护两份，容易不一致。
- **去掉面板底色，只用分隔线分区**：更平，但参数多的步骤里各组难以分辨。
- **在 Rust 侧判断系统版本并返回是否启用材质**：更直接，但需要新增依赖或解析命令输出；WebView2 的 `platformVersion` 是微软给出的 Windows 11 判断方式，足够使用。
- **在配置里固定启用材质并让框架始终透明**：Windows 10 上没有材质，框架会直接透出桌面。

## 影响

- 兼容性：核心、协议、配置与数据格式不变。原生窗口配置变化（透明、材质、默认宽度 1280），需要重新构建 EXE。
- 安全：`is_directory` 只返回布尔值；拖入的路径和手动输入的路径一样，仍由核心在扫描与处理时校验。新增的窗口权限只允许设置主题。CSP 不变。
- 可靠性：材质判断失败或系统不支持时保持不透明框架，这是安全的退化方向。若系统报告为 Windows 11 但材质未生效，框架会透出桌面——目前只能靠人工在目标系统上确认。
- 性能：前端产物增加约 25 kB（主要是拖放 API 与新组件）。透明窗口在个别显卡驱动上调整大小时可能有延迟，未测量。
- 维护：新增 `RunInspector.vue`、`core/material.ts`，删除 `ScanSummary.vue`。站点集合变为 `source / output / step:<id>`。
- 测试：组件测试覆盖概览栏的三种状态、目录外格式的保留、拖入校验、越界提示和材质判断；原生 E2E 沿用 `.dock` 约定并改为在概览栏里断言扫描说明。
