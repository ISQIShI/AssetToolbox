# ADR 0004：以处理线为骨架重构前端

状态：已采用；视觉与窗口外壳（顶栏、冷灰机壳、IBM Plex、仅浅色）被 [ADR 0006](0006-desktop-application-shell.md) 取代，处理线结构、工作区划分和全局作业栏继续有效。日期：2026-11-09。

关联：[前端设计规范](../design/frontend-design.md)、[前端架构](../architecture/frontend.md)、`desktop/src/`、`desktop/tests/`。

## 背景与约束

1.0.0 的界面是在压缩工具基础上逐步加功能形成的：处理页从上到下堆叠“提供方与获取渠道”“文件夹与保存方式”“处理步骤”三组卡片，步骤卡片纵向排列；作业进度卡片只在发起作业的页面显示完整结果。随着步骤可以排序、启用、切换组合，长滚动的卡片列表难以看清执行顺序，提供方清单常驻处理页顶部，占去大部分首屏。

用户要求全面重构前端设计，不保留对旧界面的兼容，并形成文档指导后续工作。约束：必须继续支持核心桥接提供的全部功能；不改变协议、配置、任务和报告格式；原生窗口最小 840×620；CSP 只允许本地字体。

## 决定

- 处理页改为主从结构：左侧“处理线”按执行顺序列出来源、步骤、写入和扫描结果，右侧编辑选中站点。处理线是界面唯一的强调元素。
- 顶栏分为处理、任务、恢复、工具四个工作区。处理工具清单从处理页移到独立的“工具”页，缺依赖数量显示在标签上。
- 作业改为窗口底部的全局作业栏，任何页面都能看到进度、取消和结果，直到用户关闭。预览类作业拿到结果后自动收起，结果归入所属页面。
- 状态与作业动作集中到 `core/workbench.ts`，视图通过 provide/inject 使用；源码按 `core/`、`views/`、`components/`、`styles/` 重新组织。
- 视觉上采用冷灰机壳、白色工作面、墨色主操作；彩色只表达状态，缺少依赖使用“丢失贴图”品红棋盘格。新增 IBM Plex Sans/Mono（OFL-1.1，`@fontsource` 5.3.0）打包进前端产物。
- 界面词汇统一为面向使用者的说法（处理工具、操作、写入方式等），对照表见设计规范。
- 新增开发模式下的浏览器模拟核心，便于不启动 Tauri 调整界面。

明确不包含：深色模式、拖拽排序、协议或数据格式变更。

## 备选方案与取舍

- **保留卡片布局，只换配色和字体**：改动小，但不能解决步骤顺序不清、首屏被提供方清单占据的问题。
- **步骤做成横向流程图**：直观，但 64 步、840px 宽度下无法容纳参数编辑，横向滚动也违反最小窗口约束。
- **作业结果只在发起页显示（旧行为）**：避免干扰，但跨页取消后用户需要切回原页才能看到结论。全局作业栏统一了取消和结果入口，代价是结束后需要手动关闭一次。

主从结构的代价是同一时间只能编辑一个站点；用处理线上的副标题（工具名、停用、缺依赖、文件夹名）弥补概览信息。

## 影响与验证

- 旧组件 `StepEditor`、`ProviderInventory`、`RestoreTable`、`ParameterFields` 及 `style.css` 被删除或重写；组件测试与原生 E2E 的选择器全部改为新结构（语义角色、`data-station`、`data-step-id`、`data-provider-id`、作业栏 `data-state`）。旧测试中的文件安全断言保持不变。
- 用户可见文字变化：例如“源文件夹”改为“来源文件夹”，“启用备份”改为“替换前备份原文件”，“仅重试处理失败项”改为“重试失败项”，“预览备份与恢复”改为“检查备份”。用户说明同步更新。
- 新增前端依赖须在第三方声明中登记；字体随 EXE 分发，保留 OFL 许可文本义务。
- 回退方式：还原本次提交。配置、任务和报告格式未变，不涉及数据迁移。
