# ADR 0003：资源类型、操作与实现提供方

状态：已采用。日期：2026-11-08。提供方接口、步骤版本及配置版本由 [ADR 0007](0007-operation-adapters.md) 修订；下文保留原决策背景。

后续 [ADR 0017](0017-properties-and-filters.md) 增加属性与过滤器，并修订目录、配置、任务及报告版本；三层职责继续有效。

## 背景

工具从单一压缩扩展到图片缩放等处理。原模块把格式、参数、编码器和“更小才提交”绑在一起，无法自然支持同一格式多操作、同一操作多实现或允许增大的转换。用户明确要求按新项目处理，不保留旧代码、资源和任务兼容，暂不接 Cordis。

## 决策

采用[三层扩展契约](../architecture/extensions.md)和有序 pipeline：资源类型负责识别，操作负责参数及验收策略，提供方负责执行。操作参数与实现参数按步骤隔离；任务固定三层版本和全部参数。单文件流水线结束后一次提交，复用原子写、哈希、任务锁、取消、恢复等安全设施。

迁入 PNG/pngquant、JPG/jpg-c、MP3/lame 压缩，新增 PNG/JPG 的 Sharp 缩放。恢复和备份导出保留为独立系统服务。新增 Sharp 依赖及锁文件；便携布局必须包含安装好的核心 node_modules。应用和扩展从 1.0.0 开始，配置/任务/报告分别使用 `asset-toolbox.settings/1`、`asset-toolbox.task/1`、`asset-toolbox.report/1` 字符串 schema，写入核心 `data/`。

## 取舍

继续使用小型本地注册器，不引入 Cordis 生命周期及依赖注入。收益是先形成与业务相符的边界，前端与引擎不再为每个工具增加分支；未来框架替换可围绕稳定契约验证。代价是当前执行同步、逐文件串行，Sharp 子进程有启动开销，仍需自行维护发现与版本校验。版本匹配不是二进制完整性验证。

## 旧决策与数据

本决策取代 [ADR 0002](0002-resource-toolbox-layout.md) 的处理器目录、旧接口及数据兼容约束，并修订 [ADR 0001](0001-local-process-architecture.md) 的模块边界与仅标准库假设。旧数据不加载、不转换；本工作区原数据仅归档到 Git 忽略的本地目录，应用使用新的空数据根。历史文档保留为决策背景，不参与当前开发规则。

## 验证

契约测试覆盖发现、组合与版本拒绝、参数隔离及原子配置；真实图片测试覆盖尺寸、透明度、JPEG 方向、放大、顺序、失败回滚及恢复。原有压缩、锁、续跑、重试、链接和冲突测试迁入新契约；原生 E2E 覆盖动态提供方及实际缩放。具体执行结果见[项目状态](../project-status.md)。
