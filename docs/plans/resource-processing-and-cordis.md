# 资源处理职责扩展与 Cordis 选型评估

状态：历史评估：多操作契约现已按 [ADR 0003](../decisions/0003-processing-contract.md) 实现，当前接口见[扩展契约](../architecture/extensions.md)。Cordis 仍未接入；下文描述评估时的旧代码，不作为当前实现说明。

核验日期：2026-11-08。源码基线：`96e478b`；本轮目录变更见 [ADR 0002](../decisions/0002-resource-toolbox-layout.md)。本评估依据本仓库源码、官方源码/文档和论文；没有运行 Cordis 集成基准，工期与效益是工程判断。

## 结论

**技术上可使用 DeepSeek Harness 底层的 Cordis；建议先建立多操作契约，在实际出现共享服务与插件生命周期需求时，再以适配层引入内核。当前不值得为三个压缩处理器整体替换框架。**

目标是资源处理工具，不需要引入完整 Agent Harness。即使采用 Cordis，也保留本项目的文件安全、日志、恢复和编码器适配；替换的是插件装配与生命周期机制。

## 已核实的项目与论文

- DeepSeek 官方将 Harness 描述为建立在 Cordis 上的插件化系统。其插件通过服务和事件协作，Cordis 管理加载、卸载及依赖。[官方介绍](https://www.deepseek.com/harness/zh/)
- 论文是《A Programming Paradigm for Spatiotemporal Composability》，arXiv:2608.25512。核心分别是副作用可撤销的时间可组合性，以及依赖随上下文变化的空间可组合性。论文 §6.1 明确区分受控上下文与外部文件写入，§6.3 指出不可信代码仍需外部沙箱；§5.3 的案例也不提供相对开发效率的定量结论。[论文摘要](https://arxiv.org/abs/2608.25512)、[论文全文](https://arxiv.org/pdf/2608.25512)
- 官方入门提供 `Context`、服务注入、类型化事件和可释放注册等概念，适合管理处理器注册、共享工具服务及监听器生命周期。[Cordis 入门](https://deepseek-harness.github.io/deepseek-harness/reference/cordis-primer)
- Cordis 官方仍标注 API 不稳定；所查主分支核心包为 `4.0.0-rc.12`、ESM、MIT。Harness vendor 清单则记录上游 `4.0.0-rc.11`、指定源码提交及本地补丁，包名为 `@deepseek-ai/cordis`。它与任意 `npm install cordis` 并非可假定等价的版本线。[官方仓库](https://github.com/cordiverse/cordis)、[核心包声明](https://github.com/cordiverse/cordis/blob/main/packages/core/package.json)、[Harness vendor 说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/vendor/README.md)

上述版本是核验快照，不是本项目依赖。真正试验前应锁定发布版本或提交，检查所选构建的导出、依赖和许可证；不直接复制 Harness 的整个 vendor 树。

## 当前架构的适用范围与瓶颈

现有机制很适合“增加一种压缩格式”：一个模块提供 config、校验与压缩函数，自动加入表单、CLI、预览和任务。恢复与模块加载解耦，移除编码器后仍能恢复备份。

| 现有约束及源码 | 对新职责的影响 |
| --- | --- |
| `framework/registry.js`：一个扩展名只对应一个处理器 | PNG 压缩、缩放、裁剪不能作为独立操作共存 |
| `compress.js`：输出通过同一格式校验且必须更小 | 图像放大、音量调整等正确结果可能被当成“无需压缩”；转换格式也无法直接表达 |
| schema/options：参数在全局扁平对象中唯一 | 多步骤使用同类参数或同一操作执行两次时会发生歧义 |
| `batch.js`、`tasks.js`：压缩 mode、单份 plan、`compressed` 状态 | 操作步骤、版本、输出类型、多个输出及逐步重试没有契约 |
| 启动发现、同步编码器、单作业工作进程 | 没有共享服务依赖、热卸载或任务期间版本固定机制 |

**这些首先是领域契约问题，换插件库不会自动解决。** 资源大小减少只是压缩操作的成功策略，不能变成所有操作的统一门槛。

## 建议的后续操作模型（未实现）

区分三个概念：资源类型（PNG、音频、纹理），操作（压缩、缩放、转码），提供方（具体编码器或算法）。先选一个真实需求，例如图片缩放，验证最小契约，再根据实际需求扩展。

- 操作注册以稳定 `operationId + providerId` 标识；扩展名只是输入匹配条件。同一资源可选择不同操作，不能按扫描顺序默选。
- 描述应包含 API/实现版本、参数 schema、输入/输出类型及结果验收策略。步骤配置以 step ID 隔离；可先支持单操作，后续再组合。
- 执行仅返回临时产物及元数据，核心统一校验、备份和提交。区分 `smaller-only` 与允许体积增大的正确变换；转格式和一对多输出需独立设计命名冲突与恢复记录。
- 新任务存操作/提供方版本及参数快照；旧 v1 任务显式映射到现有压缩语义。实现缺失或版本不兼容时报告不可继续，不能默用另一算法。恢复仍不依赖处理器存在。
- 作业开始后固定实现与配置；重载等待作业安全结束。插件卸载不等于强杀编码器，更不等于撤销已写入用户文件。

这些名称是设计建议，不是可调用的现有 API；采用时需另立 ADR，定义兼容层和迁移测试。

## Cordis 能接管什么

| 范围 | 使用 Cordis 的潜在收益 | 本项目仍须负责 |
| --- | --- | --- |
| 注册/依赖 | 声明服务依赖、处理器可撤销注册，减少手写启动/销毁代码 | operation/provider 冲突策略、版本兼容、错误展示 |
| 公共能力 | 复用 FFmpeg、图像解码、缓存、预览等服务并替换提供方 | 进程参数、超时、退出检查、资源限额与输出验证 |
| 事件/界面扩展 | 清理事件监听与注册项，未来可动态扩展功能入口 | Vue 组件装配、跨 Rust/Node 的序列化契约；不会自动生成桌面插件 UI |
| 运行中重载 | 管理插件上下文和依赖变化 | 作业固定版本、等待文件边界、正在运行的任务锁 |
| 文件安全 | 可用于追踪临时资源的释放 | 持久 intent/result、原子替换、哈希冲突、备份与恢复 |
| 信任边界 | 通过上下文约束服务访问 | 任意 JS 的 Node 权限、第三方插件隔离与签名/来源审查 |

拟采用时可在 Node 工作进程启动处创建上下文，通过项目自有的小适配层注册处理器；保持 Tauri JSON Lines 及已有文件核心不依赖 Cordis API。核心/Loader/Include/HMR 按需要选择，普通目录扫描无需一次引入全部组件。

## 方案比较与成本收益

| 方案 | 近期价值 | 代价与风险 | 建议 |
| --- | --- | --- | --- |
| 保留轻量发现，先抽出操作契约 | 直接支持新操作，保持便携无核心 npm 依赖 | 将来出现复杂依赖时需继续维护装配逻辑 | 当前采用的演进方向 |
| Cordis 内核 + 项目适配层 | 多处理器共享服务、依赖激活和清理可统一 | 新运行依赖、ESM/现有 CommonJS 接入、初始化顺序和打包；API 升级成本 | 有明确需求后先做隔离原型 |
| 全部业务及前后端改为 Cordis 插件 | 最大化动态组合能力 | 跨进程和 UI 重构、旧任务兼容、热卸载安全；收益暂缺使用证据 | 当前不采用 |
| 引入整个 DeepSeek Harness | 带来 Agent 模型、工具与会话体系 | 与当前资源处理需求无直接关系，依赖及部署面显著扩大 | 不采用 |

以一名熟悉项目的开发者估算：隔离原型约 2–4 人日；最小多操作契约与一个新操作约 5–10 人日；再将装配层迁到 Cordis 约额外 3–7 人日。涉及可安装第三方插件、UI 扩展或热更新时需另估，不能将它们算进以上范围。这些是未做原型前的估算，新增编码算法工作量不在其中，也没有可靠的“效率提升百分比”。

当多个操作共享解码/编码服务，或真正需要插件依赖与动态启停时，Cordis 有机会减少长期维护成本。只有几个启动时加载的独立处理器时，当前注册表很小，引入框架的初始成本更高。

## 分阶段验收与采用条件

1. **已完成**：目录、品牌和通用标识更名；压缩与持久化契约保留；全链路验证见[项目状态](../project-status.md)。
2. **下一个业务需求**：定义最小 operation/provider 契约，证明同一 PNG 可独立选择压缩或缩放，并能接受合法但变大的输出；旧任务仍可续跑/恢复。
3. **Cordis 隔离原型**：在独立试验目录锁定一个版本，包装一个现有处理器和一个共享服务；验证依赖缺失/恢复、注册释放、激活失败、卸载幂等、作业期间卸载被推迟，以及 Node 24/26 和 Windows 便携打包。
4. **量化决策**：比较启动时间、内存、发布体积、改动量和新增处理器步骤；插件异常不得影响历史恢复，原有安全回归必须全部通过。只有实际维护简化且部署增量可接受，才批准生产接入。

当前没有安装 Cordis，也没有把新的处理操作冒充已实现功能。后续框架决策应由上述原型证据和实际扩展需求推动。
