# 音频分析、增益与响度归一化

状态：已实现。三个操作共用 FFmpeg 提供方的独立适配器，遵循[扩展契约](extensions.md)与 [ADR 0008](../decisions/0008-audio-observation.md)。不接入 Cordis。

## 使用与参数

在处理线添加对应格式的操作，选择 FFmpeg；缺依赖时到“工具”页查看获取说明。各格式分别添加步骤；同一文件可先分析、再增益、再分析。

仅需筛选素材时，WAV、FLAC 支持在来源或步骤添加时长、采样率和声道条件。核心直接读取容器头，安装 FFmpeg 前也能用这些条件扫描。详见[属性读取范围](properties-and-filters.md#属性目录与扩展)。

| 操作 | 公共参数与行为 |
| --- | --- |
| `audio-analyze` 音频分析 | 无参数。读取当前步骤输入的时长、编码、采样率、声道、采样峰值、真峰值、整段 LUFS 与响度范围 LRA；不写入素材 |
| `audio-gain` 音频增益 | `gainDb` 默认 0，范围 −60～+30 dB；整段乘以 `10^(gainDb/20)` |
| `audio-normalize` 响度归一化 | `targetLufs` 默认 −18，范围 −40～−5；以目标减输入整段 LUFS 计算固定增益；−18 不是所有游戏音效的统一标准 |

两个写入操作共有 `truePeakDb`（默认 −1 dBTP，范围 −12～−0.1）和 `peakPolicy`：默认 `limit` 限制整段增益，也可选 `reject` 报错保留原文件。专属参数 `lossyQuality` 为 0～10、默认 4；越高质量越好，仅影响 MP3/Vorbis，Opus 固定 192 kb/s。没有动态压缩、自动限幅、降噪或音高/速度调整。

新配置默认另存；添加、选择或重新启用写入音频操作会选择另存。若手动改为覆盖，必须启用备份并提供有效目录，核心与前端均校验。只有分析步骤时无需输出目录，不复制素材、不生成素材备份或提交意图；仍记录持久任务和报告，支持文件边界取消与续跑。

## 支持范围与质量边界

- WAV（PCM u8/s16/s24/s32/f32/f64）、FLAC、MP3、Ogg Vorbis/Opus（`.ogg`、`.opus`）；保持编码种类、采样率与声道，不跨格式转换。
- 单音轨、单/双声道，8～192 kHz，时长大于 0 且不超过 4 小时。每次探测/测量/编码最多 120 秒、日志最多 4 MiB；长文件在慢设备上可能超时失败，不保证四小时素材均可完成。
- FFprobe 探测后，FFmpeg 完整解码并使用 `ebur128=peak=sample+true` 测量。摘要精度 0.1 dB/LU；真峰值是算法估算，不等于保证所有播放设备无失真。LRA 是响度范围，不是完整的动态范围指标，短音效尤其不宜仅据此判断听感。
- 小于 0.4 秒、静音或低于测量门限的素材显示“无法测量 / 不适用”；不根据无效 LUFS 自动放大。短音效仍可手动固定增益；静音保持原样。已有削波不能靠降低增益修复。
- 有损格式会重新编码并产生额外损失，优先从 WAV/FLAC 母版处理。非零处理移除标签、封面等元数据，游戏循环标记需要另行保留。无损编码不代表增益运算、量化对波形完全无影响。实际增益为 0 时保留原始字节。

## 峰值与结果验收

先用测得真峰值预测安全增益，并预留 0.15 dB 测量余量。超峰时整体降低增益或失败；不会只压缩峰值。编码后重新完整测量，若重建峰值仍超限，`limit` 最多从原临时输入重做三次，`reject` 直接失败。每轮都不使用上一轮有损产物。输出编码、声道、采样率和时长异常也拒绝提交。

归一化输出与目标相差不超过 0.3 LU 才标为达到；峰值受限时允许成功输出较安静的文件，但明确标记限制和未达标。后续步骤失败会丢弃所有中间结果；分析可以出现在转换前后，测得的是所在步骤的输入。

作业栏展示前 100 条音频步骤结果及警告；完整数据位于报告 `audio.csv`、`report.json` 的 `audioResults`，原始字段保留在文件步骤的 `metadata.audio`。失败文件的测量标注“未提交”。纯分析在文件统计中属于保持原样，步骤状态为 `analyzed`，不计入实际改变数。

## 依赖、来源与测试

使用 FFmpeg/FFprobe 9.0.2 Gyan essentials Windows x64（官网推荐渠道），手动获取方式及版本校验见 `providers/ffmpeg/provenance.json`。此构建启用 GPL/version3，不是 LGPL-only；源码仓库不携带 EXE，分发对应源码与组件许可尚未闭合，详见[第三方声明](../../THIRD_PARTY_NOTICES.md)。当前自动安装器不支持该大体积 ZIP/7z，未放宽限制。

核心 `audio.test.js` 验证只读、声道增益比、达标/超峰、静音/短音/损坏、多编码、原文件保护、回滚/恢复及取消；前端 `audio.test.ts` 验证参数与结果，原生 `audio.spec.ts` 在隔离生成素材上完成四种流程和缺依赖指引。测试须先按指引安装两个工具，不因缺工具静默跳过。

原理与实现依据：[FFmpeg ebur128](https://www.ffmpeg.org/ffmpeg-filters.html#ebur128-1)、[Windows 构建渠道](https://www.gyan.dev/ffmpeg/builds/)、[FFmpeg 许可说明](https://www.ffmpeg.org/legal.html)。
