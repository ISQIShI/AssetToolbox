# 常见问题

[返回用户文档](README.md)

## 下载源码后没有 EXE

首版只发布源码，GitHub 的 Source code 下载项不是安装包。按[开发与部署](development.md)构建；只用 CLI/MCP/HTTP 可以不构建桌面。不要从不明镜像下载缺少的提供方。

## 工具缺失，不能开始处理

到“工具”查看具体依赖、来源和要求版本。LAME/Sharp 支持一键安装，其他工具有手动指引。暂时不需要的功能可停用对应步骤；首次尝试 PNG 缩放时可停用默认 PNG/JPEG 压缩步骤。安装后刷新状态，详细渠道见[处理工具安装](dependencies.md)。

自动安装的来源或摘要校验失败时会保留旧安装，不要关闭校验或自行改摘要。检查网络和错误信息，必要时等待核验清单更新。

## MCP 连接不上或没有工具

- 确认 Node 24+，command 为真实 EXE 的绝对路径，server 和 policy 路径也正确。
- 执行 `npm ci --prefix agent-mcp --ignore-scripts`；复制部署时包含 package.json 和 node_modules。
- stdio 由宿主启动，不填 HTTP URL；HTTP 连接 `/mcp`，服务应已启动并带有效 Bearer 令牌。
- HTTP 端口冲突时更换端口；没有 OAuth/浏览器登录或旧式 `/sse` 接口。
- 桌面关闭导致服务停止时，重新从原入口启动；离开“工具”页本身不会停止。

先调用 `asset_capabilities` 验证，配置示例见 [MCP 指南](mcp.md)。

## PATH_FORBIDDEN 或 PERMISSION_DENIED

确认实际路径处于 policy 对应目录内，目录联接也按真实目标校验。输出、备份不是素材目录的上级；不能把核心代码或 data 当素材。覆盖、恢复、依赖安装和服务管理是不同授权开关。改 policy 后重启入口，不要用更宽泛的整盘权限掩盖配置错误。

## 提交成功但没有结果

提交仅表示作业已登记。查询 status，等待 done，检查 exitCode、errorCode 和逐文件结果；排队时作业中心显示等待原因。普通扫描预览不编码、不测音量，不会生成处理结果。相同幂等键返回原作业，不表示重新执行；确定需要新任务时使用新键。

## 图片没有变小，音频没有达到目标

压缩仅接受更小结果；缩放允许体积增加，默认仅缩小。来源过滤排除文件；步骤过滤不匹配只跳过当前步骤，且按前一步的产物重新判断。

响度归一化只施加固定增益，峰值限制可能使目标 LUFS 无法达到；静音和短音效可能无法可靠测量。不会自动动态压缩。有损音频重编码会再损失质量，处理可能移除元数据和循环标记；先比较副本及测量报告。

## 已有输出、恢复冲突或旧任务不能续跑

另存不会覆盖已有同名文件；使用新输出目录，或按任务“重试失败项”，不要手动修改任务记录。恢复核对预览时的哈希，备份或目标变化后应重新预览并检查冲突，不能强行覆盖后来修改的素材。

旧数据契约不自动迁移；旧任务不能用当前实现悄悄续跑。已有备份作为普通文件保留，可在“恢复 → 独立备份文件夹”检查并导出。取消不会回滚此前完成的文件，需要恢复时显式操作备份。

## 系统阻止运行或编译

先确认报错对应下载文件、自己编译的 EXE，还是 Rust 构建中间 DLL，检查 Windows 安全中心的具体记录。项目目前没有提供签名发行包，也不会修改系统安全策略。记录阻止原因，按自身设备管理策略处理；不要通过本项目脚本关闭保护。可在独立开发环境构建，细节见[开发指南](../docs/development.md)。

## 反馈问题

通过 [GitHub Issues](https://github.com/ISQIShI/AssetToolbox/issues)提供产品版本、Windows/Node 版本、入口、复现步骤、错误码和最小合成样本。先移除真实目录、令牌和素材；不要上传整个 `resource-core/data/`，它可能包含路径、报告和凭据。
