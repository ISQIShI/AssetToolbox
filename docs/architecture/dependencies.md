# 提供方依赖管理

状态：已实现。适用 Windows x64；决策见 [ADR 0005](../decisions/0005-managed-dependencies.md)。入口为 `resource-core/framework/dependencies/`、`desktop-bridge.js`、`ToolsView.vue`。这是可信内置提供方的依赖安装器，不是下载第三方插件的市场。

## 支持范围与版本策略

| 提供方 | 自动获取 | 渠道与核验依据 |
| --- | --- | --- |
| LAME | 4.0 x64 安装、修复与更新 | [RareWares](https://www.rarewares.org/mp3-lame-bundle.php) 固定 ZIP，SHA-256 及两个必需文件的 SHA-256；来源记录见第三方声明 |
| Sharp | 0.35.5 Windows x64 安装、修复与更新 | npm 官方 registry 的 Sharp、平台原生包、colour、detect-libc、semver 五个固定 tarball；SHA-512 来自已提交的 npm 锁文件 |
| pngquant | 手动 | 官网 Windows ZIP 仍为 2.17.0，不将其当作 3.0.3 更新；保留 Cargo 编译指引 |
| JPG-C | 手动 | 作者渠道及再分发授权未核实，不用来源不明的镜像替代 |

`catalog.json` 是随项目审核和发布的核验清单，记录目标版本、平台、精确 URL、摘要和文件映射。安装请求只接收提供方 ID，不能指定 URL、命令、路径或自定义清单。扩展的 `provenance.json` 只是手动获取说明，不能授予自动安装权限。

“更新”指升级到当前应用携带的核验清单，不联网追随 `latest`。刷新依赖状态不会下载远程清单。已有受管理安装的清单指纹变化时显示更新；已知本地版本高于目标时拒绝自动降级。手动安装不冒充已验证，用户可选择另装核验副本。

## 下载、验证与启用

1. 桌面发出 `start {mode:'dependency-install', providerId}`，桥接确认空闲，启动独立安装进程。与处理、恢复共用 `poll`、`cancel` 和安全退出流程。
2. 仅允许 HTTPS 到 `registry.npmjs.org` 或 `www.rarewares.org`，强制 TLS 证书验证；拒绝凭据 URL、额外端口及所有重定向。每个包限制 64 MiB、60 秒，取消会中止网络请求。
3. 下载完成先匹配固定摘要，再解包到全新 UUID 目录。TAR 仅接受 `package/` 下普通文件和目录；ZIP 只写清单列出的文件并核验文件摘要。拒绝路径穿越、链接、重复路径、Windows 特殊路径、加密 ZIP 和超过 128 MiB 的展开内容；不运行 npm 生命周期脚本。
4. 在短生命周期进程中检查 LAME 版本或 Sharp 加载能力，最长 15 秒。生成已安装文件的 SHA-256 清单，原子替换 `active.json` 后才算成功。
5. 失败或取消清除本次暂存目录，旧启用记录不变。进入最终原子切换后到达的取消请求可能晚于成功提交，以最终状态为准。

## 持久化、并发与信任边界

```text
resource-core/data/dependencies/<provider-id>/
  active.json                  # schema: 1，版本、清单指纹、UUID、文件摘要、时间
  installs/<uuid>/             # LAME 文件或 Sharp 的完整 node_modules 子树
```

安装器不覆盖提供方目录和手动 `node_modules`。受管理记录存在时优先使用其副本，损坏时明确阻止处理，不静默回退。刷新与处理前校验完整文件集合，拒绝文件增删、摘要变化及目录链接；版本与当前提供方不符时要求更新。

引擎在作业开始准备时固定可执行文件或 Sharp 模块路径。旧目录不删除、不原地修改，因此另一实例的更新不会破坏正在处理的快照；多个实例完成安装时，最后原子切换成功的记录生效。同一桌面会话仍仅允许一个作业。

异常断电可能留下未启用目录，不会将其自动启用。当前不自动清理历史目录，也不提供 UI 回退或卸载；关闭所有应用实例后，可人工核对 `active.json` 再清理未被引用的目录。不要删除当前使用的目录。

摘要固定值保护下载链路，安装记录用于检测本地意外损坏。安装记录与项目源码均是本地可信数据；它们不能防御已经取得本地写入权限并同时篡改源码、记录和文件的攻击者。没有代码签名升级服务、插件沙箱或后台静默更新。

## 前端与维护

工具页显示安装状态、当前/目标版本、来源域名及手动渠道。缺失时“获取并安装”，清单变化时“更新到核验版本”，损坏时“修复安装”，正常时可“重新安装”。全局作业栏显示下载、校验、安装、结果与取消；完成后自动刷新可用性，保留用户正在编辑的配置。

更新核验清单时：从原渠道重新取包，核对版本、摘要与许可，检查固定依赖闭包，更新来源记录；实现行为变化必须升级提供方契约版本，让旧任务明确拒绝。自动获取不意味着允许再分发，下载目录仍受[分发核对](../distribution.md)约束。

验证入口：`resource-core/tests/dependencies.test.js`、前端组件测试和原生 E2E。原生 E2E 会从真实渠道下载，离线/渠道故障时明确失败；不取消摘要验证来让测试通过。
