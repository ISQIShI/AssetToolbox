# 统一作业中心与入口冲突

状态：作业中心、持久队列与有限并行均已实现。单安装最多 2 个无资源冲突的作业同时执行，冲突项按登记顺序等待。完整契约见[队列与有限并行](queue.md)。

## 桌面行为

活动栏“作业”（Ctrl+5）查看桌面、CLI、stdio MCP、HTTP 和 MCP HTTP 的持久作业。每页 20 项、每 2 秒刷新，支持本页 ID/操作搜索及排队/运行/结束筛选。详情显示进度、登记顺位、等待原因、执行槽位、错误和每页 50 项结果，可取消、打开报告或进入素材任务。

JobsView.vue、core/job-center.ts 复用公共 jobs/status/results/cancel；当前应用/响应 /5、job/4。登记顺位包含运行项，不表示启动顺序或预计时间。状态只显示资源冲突、较早等待项、容量或等待派发，不公开其他权限范围的素材路径。没有可靠的入口标签，界面不猜来源。

观察状态与本会话 ActiveJob 分开：选择不提交、不接管，离开页面停止刷新。关闭纯观察窗口不取消别人作业；本会话退出取消自己的全部等待和运行项，原生宿主等待桥接退出后才结束。重复退出请求不会跳过等待。显式取消仅针对所选 ID；等待项不启动 worker，运行项等文件边界。读取失败清除旧结果，切换选择丢弃旧响应，清理后提示明细过期。

## 冲突判定与调度

源目录、输出、备份、任务及提供方构成核心推导的读写集合。读读可共享，目录父子关系和别名也参与冲突判定。整个集合一次授予，保留任务锁、逐文件哈希和恢复选择。

按序选择可运行项；与运行项或更早等待项冲突则等待，无关项可利用剩余槽位。每项 dispatch 先预约容量，worker 独立占用保护父进程崩溃窗口，退出确认前不释放预约。维护清理要求全局无等待/运行项及独占屏障。队列最多 100 个未结束作业；正常资源争用不会创建一个随后因抢锁失败的转换任务。

| 方案 | 收益 | 成本与边界 | 当前选择 |
| --- | --- | --- | --- |
| 提交时拒绝 | 简单、早报 BUSY | 需要反复重提 | 仅用于容量满等拒绝条件 |
| 严格串行 FIFO | 文件保护模型简单 | 无关资源也互相等待 | 原基线，已扩展 |
| 直接并行 | 吞吐可能提高 | 目录重叠、恢复和依赖切换不安全 | 不采用 |
| 队列＋资源锁有限并行 | 无冲突作业并行，冲突项公平等待 | 需要资源声明、启动预约、维护屏障及崩溃保护 | 已实现，最多 2 项 |

## 仍有的边界

队列由原会话共同调度，不是后台守护服务；HTTP 由服务进程持有，connection 入口退出取消自己作业。崩溃等待项不接管、不重放；素材任务显式续跑。

不同安装不共用资源锁；多个安装共享素材时优先由一个服务集中提交。外部编码器内部线程不受作业槽位精确限制。同步历史扫描尚无索引，后续可优化查询成本；后台持续执行、动态预算、优先级或跨安装协调需独立设计。
