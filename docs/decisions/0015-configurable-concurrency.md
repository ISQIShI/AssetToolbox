# ADR 0015：可配置并行预算与稳定槽位

状态：已采用。日期：2026-11-12。修订 [0014](0014-resource-aware-concurrency.md) 的固定双槽位与版本；保留资源冲突、公平性、维护屏障和原会话生命周期。

## 背景与决定

固定 2 项不能适应不同设备与负载；界面按列表顺序摆放运行作业会随完成情况移动，难以观察。采用安装级 1–8 项预算、默认 2；仅受信任本地入口且全局队列空闲时原子更新，不在运行中缩容或隐式等待应用。

CPU 可用逻辑处理器不是独立作业容量。提供方本身可能多线程，内存及磁盘也会成为瓶颈。推荐值采用 `clamp(floor(availableParallelism / 4), 1, 4)`，由操作者一键采用或手动调整；这是可解释的保守起点，尚无性能基准支持自动最优选择。

调度核心分配稳定槽位，dispatch 和 worker 占用同时校验，退出确认前不回收。公共 queue 提供活动快照；桌面按槽位编号纵向排列横向任务卡片，等待项单列，历史分页与活动快照分离。权限不足只看到匿名占用。

应用/响应升级 /6、HTTP /api/v6、job/5（data/jobs/v5）、dispatch/3、execution/2；新增 scheduling/1 配置。旧版本拒绝，不迁移。素材任务、报告、settings 和提供方契约不变。

## 替代与代价

- 直接使用 CPU 核心数：简单，但不能约束编码器内部线程，可能超配内存或降低交互响应，不采用。
- 运行中自动调节或手动缩容：需处理占用超过预算、预约和公平性，收益未经测量，本轮不采用。
- 固定 2 项：稳定但无法按机器和负载调整，改为默认值。

手动上限 8 是当前产品保护边界，不是硬件性能结论。更高上限、提供方线程/内存预算需先压测；队列仍由原持有会话调度，不能把配置持久化描述为后台服务。

实现、权限、失败行为和测试见[队列契约](../architecture/queue.md)及[验证记录](../verification/2026-11-12-configurable-slots.md)。
