# 0012：手动存储维护与测试分层

状态：已采用。日期：2026-11-10。修订 [0011](0011-unified-application.md) 的应用/响应版本及结果保留语义；保留其统一业务实现、作业身份和上下文设计。

## 背景

持久作业和报告持续增长，不能通过删除整个任务目录解决。用户选择保留最近 30 天、手动预览后清理；幂等键被删除可能重新执行旧请求。原生 UI 回归中的网络下载还会使普通交互验证受网络波动影响。

## 决定

- ApplicationService 增加 storage-preview/storage-clean，桌面与显式本地 CLI 共用；现有 policy 不包含全局维护权限，MCP/HTTP 保留动作声明但拒绝执行。
- 默认 30 天，预览不默认选择，清理使用所选 ID 和摘要。仅删除成功旧作业的明细和唯一报告；提交/执行锁、路径与文件白名单、非链接检查、摘要重验保护边界。
- 删除前保存 retention/1 状态摘要及批准清单；部分失败可重新预览继续。任务、备份、输出、依赖、作业及幂等身份永久保留至未来另行设计。
- 新增 resultsExpired/RESULTS_EXPIRED 语义，应用及 response 升级 /3，HTTP 改为 /api/v3，旧 /api/v1 和 /api/v2 返回 410。job/2 和既有目录不变，settings/task/report 不变，不引入迁移层；桌面需配套新 EXE。
- 核心源码与真实编码器测试分层且全量仍可执行；原生离线流程与真实联网安装分开。源码 CI 使用锁文件和固定官方 Action 提交，不含第三方二进制，不代替本地原生验收。

## 代价与未采用方案

不采用定时删除、删除幂等身份、自动清理备份/依赖或按任意路径清理。保留控制文件意味着不能回收全部历史空间。同步全量哈希在大数据量下可能较慢；本轮未实现流式报告、存储索引和后台清理。临时文件/未知记录保守保留，部分失败按记录报告，不承诺整批回滚。

验收及当前结果见[存储维护](../architecture/storage.md)、[测试分层](../testing.md)和[项目状态](../project-status.md)。
