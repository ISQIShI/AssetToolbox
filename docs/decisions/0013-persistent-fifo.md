# ADR 0013：持久 FIFO 与会话持有的串行调度

后续修订：[0014](0014-resource-aware-concurrency.md) 将严格串行扩展为资源感知有限并行，升级应用/响应 /5、job/4；下文保留当时决定，所有权与取消原则仍有效。

状态：已采用。日期：2026-11-11。修订 [0011](0011-unified-application.md) 的立即启动与单会话活动作业限制、[0012](0012-storage-retention-and-test-layers.md) 的应用/作业版本；保留统一业务、上下文权限和存储保护。

## 决定

不同入口争用时排队，单安装并发度 1，最多 100 个未结束作业。提交锁内登记持久序号及身份；各原持有会话共同参与调度，锁内只允许唯一队首持有者创建 dispatch 并启动 worker。既有执行锁和任务锁继续保护。出队重新核验路径、请求、版本与权限，完成必须等待退出确认。

选择会话协作调度而非立即引入后台守护进程：当前 connection/server 语义清晰，原持有者能够复用冻结权限上下文，无需持久化或从其他会话继承授权。正常退出取消自己的等待和运行项，观察者退出不影响别人；持有进程崩溃的等待项中断，不自动接管或重放。

应用/response /4、HTTP /api/v4、job/3 与新 data/jobs/v3，dispatch/1 保留启动意图。旧 HTTP 1–3 和旧作业格式明确拒绝，不迁移；素材任务、配置和提供方契约不变。存储清理保护排队项、序号、身份和 dispatch。

## 代价与替代

FIFO 队首依赖原持有会话响应；坏记录或不确定进程状态保守阻塞，无超时强抢。同步扫描尚无索引。永久后台服务、优先级、等待期限和有限并行均未实现。纯提前拒绝无法消除用户重提；直接并行缺少目录读写冲突模型。后续需要后台继续时再引入显式服务所有权，不悄悄改变 stdio/桌面退出行为。

完整状态和验证见[持久串行队列](../architecture/queue.md)，替代原[作业中心调度草案](../architecture/job-center.md)。
