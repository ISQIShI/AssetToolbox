# ADR 0014：资源感知队列与有限并行

状态：已采用。日期：2026-11-11。修订 [0013](0013-persistent-fifo.md) 的严格 FIFO 与单执行槽位；保留会话所有权、启动声明、幂等、取消和退出确认。

## 问题与决定

串行 FIFO 已避免正常入口争用失败，但互不影响的资源处理仍互相等待。采用最多 2 个作业并行、100 个未结束项的固定预算；通过源/目标/备份目录、任务与提供方读写集合判定冲突。

调度按登记顺序选择，与运行项及较早等待项均不冲突才可启动。无关项利用空闲槽位，冲突项保持 FIFO，避免后来读者饿死写者。资源整体授予，不逐个阻塞加锁；执行槽位与资源声明在 dispatch 时预约，不能等子进程抢锁才决定是否并行。

worker 的独立 execution/1 占用保护父进程死亡窗口；旧独占执行屏障转为短登记锁加共享占用检查，维护和底层直接执行仍独占。启动前重验资源快照；任务锁、哈希、原子替换与依赖不可变目录不变。

应用/响应 /5、HTTP /api/v5、job/4、dispatch/2，资源声明 resources/1；旧格式拒绝且不迁移。只有核心推导资源，调用者不能声明自己只读或提高预算。

## 替代与代价

继续串行简单但吞吐受限；直接并行无法保证目录重叠、恢复与依赖切换安全。逐文件锁能增加并发，但扫描期间新文件、目录别名和跨步骤提交使锁升级复杂，因此本轮采用保守目录范围。动态并发、优先级和后台服务暂不引入。

2 个 worker 仍可能各自使用多线程编码器，不是 CPU/内存配额；不同安装不共享资源锁。PID/token 不等同于可抵抗同权限篡改的租约。持有者卡住时保守等待，不能无证据接管或重放。

完整流程、状态、测试和限制见[持久队列与有限并行](../architecture/queue.md)。
